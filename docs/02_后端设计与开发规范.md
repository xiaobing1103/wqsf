# 万企商服通后端设计与开发规范

> 运行时：Java 21  
> 框架：Spring Boot 3.4  
> 基础包：`com.wqst.api`

## 1. 目标与边界

后端负责：

- 微信小程序和管理后台的统一 REST API。
- 登录态、角色、权限和企业数据范围校验。
- 产品模板、报单、资料、审核和补件业务。
- 私有文件上传、受控预览和访问留痕。
- Excel 客户导入、审核表导出和 ZIP 资料包导出。
- 状态日志、操作日志、通知和任务状态。

后端不负责渲染页面，不把文件二进制写入 MySQL，也不向前端返回永久公开文件地址。

## 3. 架构原则

- 采用模块化单体，不提前拆分微服务。
- 按业务域分包，每个业务域内部使用 Controller、Service、Mapper、Entity、DTO、VO 分层。
- Controller 只处理协议、参数和权限入口，不写业务规则。
- Service 是事务和状态流转的唯一入口。
- Mapper 只负责数据库访问，不处理权限和业务状态。
- Entity 不直接作为 API 响应。
- 文件、缓存、微信等外部服务通过独立 Gateway/Client 封装。

## 6. REST API 规范

### 6.1 基础路径

所有正式接口使用版本前缀：

```text
/api/v1
```

客户端和后台共用资源路径，通过权限区分操作范围。管理动作可以使用明确子资源，例如：

```text
GET  /api/v1/cases
POST /api/v1/cases/{caseId}/submit
POST /api/v1/admin/materials/{materialId}/review
```

### 6.2 HTTP 方法

- `GET`：读取，不产生业务状态变更。
- `POST`：创建或执行明确命令。
- `PUT`：完整更新，项目中尽量少用。
- `PATCH`：局部更新。
- `DELETE`：软删除或解除关系，不物理删除核心记录。

状态流转使用命令式子路径，不通过任意修改 `status` 字段实现。

### 6.3 统一响应

```json
{
  "success": true,
  "code": "OK",
  "message": "操作成功",
  "data": {},
  "requestId": "01J8...",
  "timestamp": "2026-09-23T16:30:00+08:00"
}
```

分页响应：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 128,
  "totalPages": 7
}
```

### 6.4 HTTP 状态码

| 状态码 | 用途 |
| --- | --- |
| `200` | 查询或命令成功 |
| `201` | 创建成功 |
| `400` | 参数格式错误 |
| `401` | 未登录或令牌失效 |
| `403` | 已登录但无权限 |
| `404` | 资源不存在或无权感知该资源 |
| `409` | 状态冲突、重复提交、乐观锁冲突 |
| `413` | 文件过大 |
| `415` | 文件类型不支持 |
| `422` | 业务校验不通过 |
| `429` | 请求过于频繁 |
| `500` | 未预期服务端错误 |

## 7. 错误码规范

错误码使用模块前缀：

| 错误码 | 含义 |
| --- | --- |
| `AUTH_REQUIRED` | 需要登录 |
| `AUTH_PERMISSION_DENIED` | 权限不足 |
| `COMPANY_NOT_FOUND` | 企业不存在 |
| `CASE_NOT_FOUND` | 报单不存在 |
| `CASE_STATUS_CONFLICT` | 当前状态不允许执行操作 |
| `MATERIAL_REQUIRED` | 必填资料未完成 |
| `MATERIAL_REVIEW_CONFLICT` | 审核结果已被他人更新 |
| `FILE_TYPE_NOT_ALLOWED` | 文件格式不支持 |
| `FILE_SIZE_EXCEEDED` | 文件大小超限 |
| `FILE_ACCESS_DENIED` | 无权访问敏感文件 |
| `IMPORT_TEMPLATE_INVALID` | 导入模板不匹配 |
| `EXPORT_JOB_FAILED` | 导出任务失败 |

异常响应不得返回数据库 SQL、对象存储密钥、堆栈或服务器物理路径。

## 8. 参数校验

- Controller 请求对象统一使用 `@Valid`。
- 字符串先去除首尾空格，再做长度和格式校验。
- 手机号、邮箱、统一社会信用代码采用独立校验器。
- ID 必须大于 0。
- 枚举通过明确枚举类型解析，禁止业务代码比较散落字符串。
- 文件扩展名、声明 MIME 和实际文件头必须同时校验。

示例：

```java
public record CreateSimpleCaseRequest(
    @NotNull Long productId,
    @NotBlank @Size(max = 64) String legalPersonName,
    @NotBlank @Size(max = 128) String companyName,
    @NotBlank @ChinaMobile String contactPhone
) {}
```

## 9. 认证与授权

### 9.1 登录场景

使用 Sa-Token 隔离两个登录场景：

- `CLIENT`：微信小程序用户，通过 `code` 换取 OpenID 后登录。
- `ADMIN`：后台用户，通过用户名和密码登录。

后台密码使用 BCrypt 或 Argon2 哈希。连续失败需要限流并记录登录日志。

### 9.2 Token 传递

统一请求头：

```text
Authorization: Bearer <token>
```

前端不得把令牌写入 URL。日志过滤器必须遮蔽 Authorization。

### 9.3 权限编码

建议权限：

```text
dashboard:view
case:view
case:create
case:assign
case:review
product:view
product:edit
company:view
company:import
file:sensitive:view
export:excel
export:zip
audit:view
```

Controller 使用权限注解，Service 再校验数据范围。只有按钮权限，没有数据范围校验是不完整的授权。

### 9.4 数据范围

- 客户用户只能访问其已绑定企业的报单。
- 普通运营只能访问分配给自己或所属团队的报单。
- 敏感资料预览需要 `file:sensitive:view`。
- ZIP 导出需要 `export:zip`，不能由普通 Excel 权限隐式获得。

无权访问时返回 404 还是 403，由是否允许用户感知资源存在决定。企业间数据隔离默认返回 404。

## 10. 报单与状态机

### 10.1 创建报单

创建操作必须在一个事务中：

1. 验证用户与企业关系。
2. 验证产品已上架且资料模板已发布。
3. 创建 `service_case` 草稿。
4. 根据模板生成 `material_submission` 快照。
5. 写入初始 `case_status_log`。

### 10.2 提交报单

提交前校验：

- 简表单的 3 个字段完整。
- 贸易增量必填文字字段格式正确。
- 必填文件处于 `READY` 状态。
- 用户已确认服务协议和隐私政策。

使用乐观锁或条件更新避免重复提交：

```sql
UPDATE service_case
SET status = 'PENDING_REVIEW', submitted_at = NOW(3), version = version + 1
WHERE id = ? AND status = 'DRAFT' AND version = ?;
```

影响行数不是 1 时返回 `CASE_STATUS_CONFLICT`。

### 10.3 审核

审核一个资料项时：

1. 校验报单状态允许审核。
2. 校验审核人员数据范围。
3. 更新资料当前审核状态。
4. 新增 `material_review_log`。
5. 必要时生成补件请求并更新报单状态。
6. 写入 `case_status_log` 和 `operation_log`。

客户可见说明与内部备注必须使用不同字段和不同 VO，避免误返回内部内容。

## 11. 文件服务设计

### 11.1 上传流程

首期采用后端代理上传，降低微信域名、S3 签名和跨域配置复杂度：

```text
客户端 -> Spring Boot multipart -> 文件校验 -> SeaweedFS S3 -> file_object
```

默认建议：

- 图片：单文件不超过 10 MB。
- PDF：单文件不超过 30 MB。
- Excel：单文件不超过 20 MB。
- MP4：单文件不超过 100 MB。

实际限制由模板项配置和服务端全局上限共同决定，取较小值。

### 11.2 文件校验

- 原始文件名只用于展示。
- 对象键由服务端生成 UUID。
- 禁止 `..`、绝对路径和控制字符。
- 使用文件头识别实际格式，不能只信任扩展名。
- 计算 SHA-256，用于完整性校验和可选去重。
- 上传成功后才写 `READY`；失败写 `FAILED` 并返回可重试错误。

### 11.3 受控预览

前端请求预览时：

1. 后端校验登录、报单数据范围和敏感权限。
2. 写入 `file_access_log`。
3. 生成 1–5 分钟有效的签名 URL，或由后端流式转发。
4. 返回给前端，禁止缓存为长期业务字段。

签名 URL 不写入普通日志。

## 12. Excel 客户导入

使用 EasyExcel 流式读取，避免整表加载到内存。

流程：

1. 创建 `import_job`。
2. 校验模板标识和列头。
3. 逐行标准化、校验和去重。
4. 以小批次事务写入企业、用户和企业关系。
5. 失败行写入 `import_job_error`。
6. 生成脱敏错误报告。
7. 更新任务统计和最终状态。

导入幂等键推荐使用“统一社会信用代码”；缺失时使用规范化企业名称加联系人手机号哈希作为弱幂等键，并要求人工确认。

## 13. Excel/ZIP 导出

### 13.1 审核表 Excel

可以包含：

- 报单编号、企业名称和服务类型。
- 资料项名称、提交状态、审核结果和客户可见备注。
- 负责人、提交时间、完成时间。

不得包含：

- 身份证、征信、网银文件内容。
- 完整基本户账号。
- 对象存储地址或签名 URL。

### 13.2 原始资料 ZIP

仅贸易增量报单生成，目录固定为 `01` 至 `11`，附带审核表。生成前再次校验 `export:zip` 权限。

ZIP 条目名必须清理路径字符，防止 Zip Slip。生成过程使用流式写入，禁止把所有文件一次性读入内存。

### 13.3 异步任务

首期不引入消息队列：

- 创建任务后状态为 `PENDING`。
- 线程池执行任务，使用条件更新抢占为 `RUNNING`。
- 成功写入对象键和过期时间，状态改为 `SUCCEEDED`。
- 失败记录对用户安全的原因，状态改为 `FAILED`。

任务必须幂等。多实例部署时通过数据库条件更新或 Valkey 分布式锁保证同一任务只执行一次。

## 14. Valkey 使用规范

键格式：

```text
wqst:<环境>:<模块>:<业务键>
```

示例：

```text
wqst:prod:auth:client:<token>
wqst:prod:idempotency:case-submit:<userId>:<key>
wqst:prod:rate:file-preview:<userId>
wqst:prod:export:lock:<jobId>
```

- 每个业务键必须设置 TTL。
- 禁止使用 `KEYS *`。
- 缓存只加速读取，不作为唯一业务数据来源。
- 删除数据库数据时同步删除或失效相关缓存。

## 15. 事务、幂等和并发

- `@Transactional` 放在 Service 公共方法上。
- 网络调用不得放在长事务中。
- 状态流转使用条件更新。
- 前端创建、提交、导出操作携带 `Idempotency-Key`。
- 后端使用“用户 + 接口 + 幂等键”在 Valkey 保存结果摘要。
- 乐观锁冲突返回 409，由前端刷新数据，不静默覆盖。

## 16. 日志与审计

应用日志至少包含：

- `requestId`。
- 当前用户 ID，不记录令牌。
- HTTP 方法和路径，不记录敏感查询参数。
- 响应状态、耗时和错误码。

业务审计记录：

- 分配负责人。
- 审核、补件和状态变更。
- 敏感文件预览、下载。
- Excel/ZIP 创建和下载。
- 产品模板发布和上下架。

禁止记录：完整手机号、税号、银行账号、身份证内容、征信内容、文件签名 URL、密码和微信密钥。

## 17. MyBatis-Plus 规范

- Mapper 方法优先使用类型安全条件构造器。
- 复杂列表查询使用明确 XML SQL，不拼接用户输入。
- 分页查询必须有稳定排序，通常使用 `created_at DESC, id DESC`。
- 更新必须带业务条件或主键，禁止无条件 `update` / `delete`。
- 批量 `IN` 数量超过 500 时分批处理。
- Entity 使用 `@Version` 标注乐观锁字段，软删除使用明确时间字段而不是模糊布尔值。

## 18. 安全规范

- 所有生产接口启用 HTTPS。
- CORS 只允许明确的后台域名；微信小程序走已配置合法域名。
- 上传接口限流并限制请求体大小。
- 敏感字段在应用层加密，密钥来自部署环境。
- 对象存储桶必须私有。
- 管理后台登录、敏感预览和导出建议启用二次确认或短时授权。
- 对外错误信息不暴露内部实现。
