## 3. Excel 用例模板

配套工作簿共四个工作表：

- `执行总览`：自动统计总用例、通过、失败、阻塞、未执行和通过率。
- `全流程用例`：111 条手工用例，覆盖环境、认证、后台、小程序、报单、审核补件、品类匹配、导入导出、审计和安全边界。
- `测试数据`：可直接复制的合成账号、企业、开票和品类匹配数据。
- `缺陷记录`：登记复现步骤、预期、实际结果、截图或 `requestId`、负责人和回归结果。

执行每条用例时填写黄色列：

1. “实际结果”写事实，例如“HTTP 200，列表显示 3 条”，不要只写“正常”。
2. “状态”选择 `未执行`、`通过`、`失败`、`阻塞` 或 `不适用`。
3. 失败时在“缺陷记录”新增一行，并把缺陷编号回填到用例。
4. 阻塞时说明缺少的账号、环境、外部密钥或业务数据。
5. 不得录入真实身份证、征信、网银密码、U 盾密码、银行账号或生产密钥。

## 4. 推荐执行顺序

### 4.1 环境和两套登录

执行 `ENV-001` 至 `ENV-007`、`AUTH-001` 至 `AUTH-010`。

1. 后台使用超级管理员登录，验证错误密码、刷新恢复、退出确认和重新登录。
2. 小程序切换到账号登录，使用客户账号登录。
3. 验证错误密码、本地模拟微信登录、退出并切换账号。
4. 未配置正式微信 AppID/AppSecret 时，正式微信登录失败属于预期限制，不得记成通过。

### 4.2 后台基础模块

执行 `ADM-*`、`COM-*`、`TEAM-*`、`PROD-*`。

1. 依次点击运营工作台、报单管理、客户资料、数据导出、业务模板、团队与权限。
2. 新增合成企业，验证查看、编辑、客户账号发放、密码重置和软删除。
3. 新增合成后台成员，分配角色，再使用该账号验证菜单和接口权限。
4. 验证产品、模板版本、发布和下架。使用 `TEST_*` 合成编码，不直接修改既有业务模板。

### 4.3 小程序页面和导航

执行 `CLI-*`、`DATA-*`、`MSG-*`。

重点观察：

- 所有页面只出现一个微信原生头部。
- 首页输入框、卡片和“全部服务/查看全部”边框不丢失。
- 底部只保留“首页 / 品类匹配 / 我的”。
- 报单列表是二级页面，不作为 TabBar。
- “我的”只保留企业资料入口和四类可点击的报单统计，不内嵌报单列表。
- 企业资料只能看到当前账号有权访问的企业。

### 4.4 贸易增量报单闭环

执行 `CASE-001` 至 `CASE-022`。

```text
客户创建草稿
  -> 填写文字资料、上传文件和开票资料
  -> 客户提交
  -> 后台单项审核
  -> 后台发起补件
  -> 客户收到通知并补件重提
  -> 后台分配经办人
  -> 状态变更为处理中和已完成
  -> 客户在分类列表查看最新状态
```

安全要求：

- 上传文件必须是合成图片/PDF，不得包含真实个人信息。
- 网银、U 盾、交易密码只能由管理员登记“线下交接状态”，不得在小程序上传或在数据库保存秘密原文。
- 分别验证“客户可见说明”和“内部备注”。
- 两个窗口使用旧 `version` 重复审核时，应返回乐观锁冲突。

### 4.5 商标、资质和品类匹配

执行 `SIMPLE-*`、`CAT-*`。

1. 分别创建商标注册咨询和资质申报简表，验证必填、同意勾选、保存、提交和后台状态流转。
2. 品类匹配上传合成营业执照图片。未配置腾讯云 OCR 密钥时，应降级为手工填写。
3. 输入 `软件开发；信息技术咨询；电子产品销售`，验证真实规则命中。
4. 输入无关键词文本，必须显示空状态，不得伪造推荐。

### 4.6 导入、导出、审计和权限边界

执行 `IMP-*`、`EXP-*`、`AUD-*`、`SEC-*`。

1. 下载企业导入模板，用合成 Excel 测试成功导入和错误报告。
2. 创建审核 Excel 与资料 ZIP 导出，轮询任务并下载。
3. 检查操作、文件访问和下载日志。
4. 使用不同客户和受限管理员测试数据隔离与 403。
5. 验证同一幂等键不会产生重复报单、重复提交或重复补件。
6. 检查控制台和后端日志，不得出现密码、Token、银行秘密原文。

## 6. 用户自行重新启动

### 基础设施

```powershell
docker compose -f infra/docker-compose.yml up -d
docker compose -f infra/docker-compose.yml ps
```

### 后端构建

```powershell
cd services/api
mvn -DskipTests package
cd ../..
```

当前推荐使用 Linux JRE 容器运行，避免本机 Java loopback 异常。按根目录 `README.md` 的本地后端容器命令重建。管理员引导变量应使用数据库中不存在的用户名；同名账号不会被覆盖。

### 管理后台

```powershell
cd apps/admin-web
pnpm dev --host 0.0.0.0
```

### 小程序 H5

```powershell
cd apps/client-uni
pnpm dev:h5 --host 0.0.0.0 --port 5175
```

### 微信 development 包

```powershell
cd apps/client-uni
pnpm dev:mp-weixin
```

## 7. 出现问题先看哪里

| 问题 | 第一检查位置 |
| --- | --- |
| 容器未健康 | Compose `ps` 和对应 `docker logs` |
| 后端 8080 不通 | `docker logs --tail 200 wqst-api-dev`、MySQL/Valkey 状态 |
| 管理后台白屏 | 浏览器 Console/Network、后台 Vite 代理 |
| 小程序接口不通 | `.env.development`、小程序 Vite 代理、微信域名校验设置 |
| 双头部 | `pages.json`、开发者工具是否导入旧包 |
| 页面不能点击 | “选择页面元素”模式、全屏遮罩层 |
| 客户登录失败 | `AuthService`、`user_account`、Valkey 失败计数和账号状态 |
| 报单/资料越权 | `SecuritySupport`、企业成员关系和响应 `requestId` |
| 导出失败 | `export_job`、后端日志、SeaweedFS 状态 |
| 品类匹配为空 | 19 条启用规则和输入关键词 |
