# TekMark 卡片 CTA 与页脚细节还原

> 日期：2026-10-09  
> 序号：005  
> 类型：修复 / 前端静态页面  
> 状态：已完成

## 1. 为什么要修改

卡片 CTA 和页脚导航仍按 375px 固定尺寸显示，与提供的约 600px 参考稿相比整体偏小。具体表现为 CTA 标题和按钮比例不一致、页脚三栏位置不准、版权与社交区域过于紧凑。

## 2. 修改文件清单

| 文件 | 类型 | 修改内容 |
| --- | --- | --- |
| `tekmark-card.html` | 修改 | 恢复 600px 设计基准，校准 CTA、页脚三栏、版权、地址、社交图标和底部区域 |
| `docs/03_前端设计与开发规范.md` | 修改 | 记录 600px 基准和 375–600px 响应式规则 |
| `docs/changes/README.md` | 修改 | 登记本次变更记录 |

## 3. 修改前后的逻辑

### 修改前

- 页面最大宽度固定为 375px。
- CTA 按钮占满卡片内部宽度，比参考稿明显更宽。
- 页脚第一列使用 `1.1fr`，三列起始位置不一致。
- 字体、社交图标、版权区和底部分隔线均按 375px 尺寸固定。

### 修改后

- 页面最大宽度恢复为 600px。
- 通过 `clamp()` 在 375–600px 之间连续调整尺寸，窄屏仍保持原有紧凑比例。
- 卡片展示图保持整页宽度，CTA 使用约 30px 外边距和 24px 圆角。
- CTA 标题使用更接近参考稿的粗体字形，按钮最大宽度约 403px 并居中。
- Products、Support、Legal 改为三列等宽，栏目、链接、版权、地址、社交图标和退订区域按参考稿重新校准。

## 6. 验证结果

- 参考图测量：CTA 参考图为 629×739，页脚参考图为 624×413。
- Chrome Headless 本地渲染：已按 600px 页面宽度生成完整截图，并分别裁切 CTA 与页脚进行视觉对比。
- 静态检查：600px 最大宽度、响应式尺寸、CTA 按钮宽度、三列等宽布局均已写入。
- 未执行单元测试、集成测试、容器实跑、真实邮件客户端或生产验证。

## 7. Bug 定位和回退

- CTA 比例异常：检查 `.card-art`、`.cta-card`、`.cta-card h2` 和 `.cta-card .primary-button`。
- 页脚列错位：检查 `.footer-links` 的等宽网格与 `--page-pad`。
- 窄屏尺寸异常：检查各处 `clamp()` 的最小值、首选值和最大值。
- 回退方式：将页面最大宽度恢复为 375px，并恢复本次修改前的固定像素值；不涉及接口和数据库回滚。

## 8. 已知限制

- 字体使用系统自带 Arial/Arial Black，不同操作系统的字形可能存在轻微差异。
- 尚未在 Outlook、Gmail 等真实邮件客户端中验证 CSS Grid 与 `clamp()` 支持情况。
- 商务背景图和联系人头像仍是占位区域，不属于本次两处样式修复范围。
