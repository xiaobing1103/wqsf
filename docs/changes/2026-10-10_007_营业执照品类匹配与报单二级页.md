# 营业执照品类匹配与报单二级页

> 日期：2026-10-10  
> 序号：007  
> 类型：功能 / 配置 / 数据库 / 文档  
> 状态：部分完成（真实 OCR 待配置腾讯云凭据后验收）

## 1. 为什么修改

原小程序把“报单”放在底部导航，占用了一级入口；用户希望报单回到首页进入的二级流程，并把中间入口替换为“品类匹配”。品类匹配需要上传营业执照、识别公司名称与经营范围，再推荐可做品类。项目原先没有独立 OCR 接口和行业品类规则，现有报单文件接口又强制依赖报单与资料项，不能安全复用。

## 3. 修改前后的逻辑

### 修改前

```text
底栏报单 -> 服务选择 -> 创建报单
营业执照只能作为已创建报单的资料附件上传
没有 OCR，也没有经营范围到品类的映射
```

### 修改后

```text
首页开始报单 -> 服务选择二级页 -> 创建报单

底栏品类匹配
  -> 选择营业执照图片
  -> 本项目后端校验 JPG/JPEG/PNG、10MB、文件头
  -> 腾讯云 BizLicenseOCR（不保存图片）
  -> 用户核对或手工填写公司名称/经营范围
  -> 后端查询 business_category_rule 并计算命中
  -> 小程序按行业显示品类、命中词和规则分数
  -> 进入服务选择二级页
```

OCR 未配置或失败时，只跳过自动回填，手工匹配仍可用。

## 4. 接口、数据库和前端影响

- 接口：新增 `POST /api/v1/category-match/recognize` 和 `POST /api/v1/category-match/recommend`；新增 `OCR_NOT_CONFIGURED`、`OCR_NO_BIZ_LICENSE`、`OCR_SERVICE_UNAVAILABLE`。
- 数据库：新增 `business_category_rule` 和 19 条基础规则，不保存营业执照图片或 OCR 原文。
- 前端：新增品类匹配一级页面；底栏移除报单；服务选择和报单资料页明确为二级页面。
- 配置：服务端新增 `TENCENTCLOUD_SECRET_ID`、`TENCENTCLOUD_SECRET_KEY`、可选 `TENCENTCLOUD_OCR_REGION`、`TENCENTCLOUD_OCR_ENDPOINT`。密钥不得配置到小程序。

## 7. Bug 定位和回退

- 页面或底栏先看 `BottomNav.vue`、`pages/category/match.vue` 和 `pages.json`。
- OCR 上传先看 `api/category-match.ts` 和后端 `BusinessLicenseOcrClient`，按错误码区分配置、图片和上游故障。
- 推荐结果先查 `business_category_rule`，再看 `CategoryMatchService`；关键词用英文逗号分隔。
- 新库有 19 条规则但中文经营范围零命中时，检查 `004_category_match.sql` 是否仍有 `SET NAMES utf8mb4`，并确认初始化顺序为 001–004。本轮集成测试首次执行时捕获了该字符集问题，修复后全量重跑通过。
- 回退代码后重新执行 `pnpm api:sync`。数据库回退可删除 `business_category_rule`，但生产环境执行前必须备份并确认没有人工维护数据。

## 8. 已知限制

- 未提供腾讯云凭据，因此真实营业执照 OCR 尚未完成外部服务验证；当前只验证了无凭据降级分支。
- 19 条规则是首批通用品类，不是参考产品完整的 17 行业/180+ 品类库。
- 当前没有后台品类规则维护页面，也没有语义模型；需要管理员通过 SQL 维护关键词。
- 规则分数是命中词数量生成的解释性分数，不代表统计概率或准入结论。
