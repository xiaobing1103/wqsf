## 1. 为什么要修改

发送后，邮件客户端出现蓝色按钮背景消失、页脚内容贴边和头像遮住姓名。原文件面向浏览器，关键布局依赖 `<style>` 内的 CSS Grid、Flex、绝对定位、CSS 变量与 `clamp()`；部分邮件客户端会忽略这些声明或只保留部分样式。

## 3. 修改前后的逻辑

### 修改前

- 页面依赖浏览器 CSS 选择器和现代布局属性。
- 头像用绝对定位压在资料卡上；当邮件客户端忽略资料区域的间距时，会覆盖姓名。
- 蓝色 CTA 和页脚 Shop cards 按钮依赖 CSS 背景，部分客户端只剩白色链接文字。

### 修改后

- 邮件主体用 `role="presentation"` 的表格，最大宽度 600px，并给 Outlook 提供 600px 条件表格。
- 蓝色按钮使用表格单元格 `bgcolor` 与行内 `background-color` 双重声明。
- 背景图、头像、姓名、职位、按钮依次占独立表格行；头像图片只能放进 `.avatar-placeholder`，姓名不会与头像处在同一布局层。
- 页脚品牌区、三栏链接、社交图标、分隔线均由表格单元格控制，文字尺寸与颜色直接写在元素上。
- 保留已有文案、线上图片、模板变量与外部跳转地址；窄屏使用简单媒体查询调整字体和栏位。

## 4. 接口、数据库和前端影响

- 接口：无变化。
- 数据库：无变化。
- 前端：根目录独立邮件 HTML 的 DOM 结构与样式变化；业务应用页面和路由不受影响。
- 发信接入：必须使用更新后的完整 HTML，并在发送前填充联系人资料与头像。若发信系统持有独立的旧模板，还需同步替换其内容。

## 5. 目录结构变化

无新增、删除或移动目录与关键文件。

## 6. 验证结果

- 静态检查：没有绝对定位、Grid、Flex、CSS 变量与 `clamp()` 作为关键布局；头像和姓名处在连续的独立表格行。
- 浏览器本地渲染：Chrome Headless 成功渲染 600px 布局；资料卡姓名位于头像下方，CTA 与页脚按钮显示蓝色背景。
- 未执行单元测试、集成测试、容器实跑、真实邮箱客户端发信复验或生产验证。

## 7. Bug 定位和回退

- 邮件中仍见旧样式：检查实际发信 HTML 是否已换成根目录 `tekmark-card.html`，是否由平台缓存了旧模板。
- 头像覆盖姓名：检查头像是否插入 `.avatar-placeholder` 所在表格行，是否额外注入了 `position:absolute`。
- 按钮背景消失：检查按钮的 `td bgcolor="#087ff5"` 是否被发信平台清理。
- 回退方式：恢复旧版 `tekmark-card.html` 及对应文档记录；不涉及接口或数据库回滚。

## 8. 已知限制

- 商务背景图和头像文件尚未随模板提供，当前仍保留占位区域。
- Outlook Classic 对圆角的支持有限，圆角可能呈直角，但布局和内容顺序应保持稳定。
- 真实邮箱客户端尚未复验，尤其应检查截图所用客户端、Gmail 和 Outlook。
