## 1. 为什么修改

H5 宽屏查看 M04 开票页面时，`uni-input` 使用 `width: 100%` 的同时仍按 `content-box` 计算左右 padding，输入框实际宽度超过所属网格列，造成公司名称与税号等相邻字段重叠。浏览器批注工具还在左下角叠加像素角色，视觉上进一步遮挡按钮，但该角色不属于项目 DOM。

代码 Review 另外发现：已有开票信息时点击“重新填写”，底部“保存并继续”会因为 `invoiceSaved=true` 直接切换到附件页，可能丢失尚未点击单独保存按钮的修改。

## 3. 修改前后的逻辑

### 修改前

```text
网格列宽 389px
  -> uni-input width:100% + 左右 padding
  -> 实际外框约 433px
  -> 跨入相邻网格列

重新填写 -> 点击“保存并继续” -> 未保存修改，直接进入附件页
```

### 修改后

```text
网格列 min-width:0
  -> uni-input 使用 border-box
  -> 外框宽度严格等于网格列宽

重新填写 -> 点击“保存并继续” -> 校验并保存开票信息 -> 进入附件页
```

## 7. Bug 定位和回退

- 输入框再次跨列：在浏览器检查 `.form-field` 与 `uni-input` 的 `getBoundingClientRect()`，确认 `box-sizing` 为 `border-box` 且左右边界未超过网格列。
- 重新填写丢失：检查 `nextStep()` 是否同时判断 `!invoiceSaved` 和 `editingInvoice`，以及 `saveInvoiceForm()` 是否成功刷新详情。
- 左下角像素角色：页面 DOM 和项目截图均不存在该元素，应关闭浏览器“批注”悬浮工具，而不是在业务 CSS 中隐藏未知外部节点。
- 回退时只需恢复 `invoice.vue` 的本次盒模型与 `nextStep()` 修改；无需回退接口或数据库迁移。
