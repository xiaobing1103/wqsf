## 1. 为什么修改

小程序第一批只完成了 M01 首页、M02 服务选择和 M03–M06 路由骨架，企业用户还不能在真实页面创建贸易增量草稿、填写 11 项资料、上传附件、提交审核或查看报单进度。

本次按已确认的第二批范围打通贸易增量报单闭环，并使用明确标记为本地演示的合成数据实跑。小程序不提供网银登录密码、U 盾密码、交易密码、短信验证码等认证秘密的输入或上传入口。

## 3. 修改前后的逻辑

### 修改前

```text
M02 选择贸易增量 -> M03 阶段占位
M04 / M06 -> 固定说明文案，没有真实资料、上传和报单列表
```

### 修改后

```text
M02 选择贸易增量
  -> 按企业 + 产品 + 月份精确恢复可编辑草稿，或携带 Idempotency-Key 创建草稿
  -> M03 读取报单详情和产品资料模板
  -> M04 保存 8 项开票信息 / 上传 9 类附件 / 保存水母报告 URL
  -> M03 提交前重新检查 11 项必填资料
  -> 携带 Idempotency-Key 提交审核
  -> M06 查看真实分页报单、状态和资料完成度
```

草稿 Store 只在本地保存当前草稿编号和幂等键，不缓存开票敏感字段或文件内容。已保存的税号、联系电话和基本户账号只显示后端返回的掩码。多企业场景下，恢复草稿会同时校验企业、产品、月份、服务类型和可编辑状态，避免误打开其他企业草稿。

## 7. Bug 定位和回退

- 草稿创建或恢复异常：先看 `stores/caseDraft.ts` 的企业/产品/月度匹配和创建幂等键，再查 `POST /api/v1/cases` 响应。
- M03 数量或顺序异常：检查 `getCaseDetail` 返回的资料快照、产品模板的 `sortOrder` 和 `MaterialItem.vue`。
- 开票保存失败：检查 `invoice.vue` 前端格式校验、`caseInvoice` 响应和后端脱敏字段。
- 上传失败：检查 `useFileUpload.ts` 的前置校验、`upload.ts` multipart 请求、模板扩展名/大小/数量以及后端 `FILE_*` 错误码。
- 提交提示缺资料：重新获取报单详情，核对 `missingMaterials` 与后端提交校验；前端完成度不能代替后端校验。
- 回退时恢复本次小程序源码和文档即可；本次没有数据库迁移。若要清理合成报单，必须只处理编号 `BD20261009171053A6FB` 及其关联演示文件，不得删除 Docker Volume 或其他本地数据。
