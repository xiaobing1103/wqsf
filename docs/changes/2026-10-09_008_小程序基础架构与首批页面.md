## 1. 为什么修改

小程序此前仍是单页静态原型：根 `App.vue` 和 `pages/index/index.vue` 重复渲染，M01–M06 路由没有建立，页面显示硬编码假数据，也没有 Pinia 会话、企业和目录状态。与此同时，项目缺少 H5 与微信平台编译包，H5/微信构建都因 Vue 导出不匹配失败。

本次按已确认的第一批范围恢复构建链，建立可继续迭代的应用基础层，接入本地客户登录、企业身份、真实服务目录和最近报单，完成 M01 首页与 M02 服务选择；M03–M06 只保证路由有效并明确标注未完成边界。

## 3. 修改前后的逻辑

### 修改前

```text
pages/index/index.vue -> 再次渲染 App.vue -> 静态假数据和页面内 Tab 切换
构建 -> 缺少平台包 -> H5/微信均失败
```

### 修改后

```text
App 启动 -> Pinia auth.ensureSession
  H5 -> dev-login -> auth/me
  微信 -> uni.login -> wechat/login -> auth/me

M01 -> 领域 API -> 企业 + 已发布服务 + 最近报单
M02 -> 已发布服务目录 -> 贸易增量到 M03 / 其他服务到 M05
```

页面不直接调用 `generated/endpoints.ts`。本地 Token 只用于请求认证；不在 Store、页面、日志或缓存中保存网银密码、U 盾密码、交易密码和验证码。

## 4. 接口、数据库和前端影响

- 接口：无路径、请求、响应或错误码变化；复用既有登录、当前用户、企业、目录和我的报单接口。
- 数据库：无表、字段、索引和种子数据变化。
- 前端：小程序从单页静态原型变为真实 M01/M02 和 M03–M06 路由骨架；H5 联调改为同源代理。
- 配置：增加 H5 Vite 代理；微信正式环境仍需通过 `VITE_API_BASE_URL` 配置可访问的 HTTPS API 地址。

## 7. Bug 定位和回退

- 构建出现 Vue/DCloud 导出错误：先看 `package.json` 中所有 `@dcloudio/*` 是否保持同一版本，以及 `@dcloudio/types` 是否为 `uni-app` 声明的 Peer 版本。
- H5 显示 `request:fail`：先看 `vite.config.ts` 的 `/api/v1` 代理和 `8080` 后端 Health，再查浏览器网络请求。
- 登录失败：H5 检查 local Profile 是否开启 `dev-login`；微信检查 AppID/AppSecret、合法域名和 `uni.login` 返回码。
- 首页数据异常：依次检查 `stores/auth.ts`、`stores/company.ts`、`stores/catalog.ts` 和 `pages/home/index.vue` 的局部失败提示。
- 回退时恢复旧 `App.vue`、`pages.json` 和 `pages/index/index.vue`，删除本次新增目录并恢复依赖锁文件；无需回退数据库或接口。
