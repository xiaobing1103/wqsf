## 1. 为什么修改

微信开发者工具 Nightly 中，首页进入服务选择、企业资料等页面后仍出现两个微信胶囊。源码已经删除页面内自定义头部，因此需要同时核对生成配置和开发者工具实际打开的项目窗口。

二次复核时发现电脑上同时运行两个项目窗口：标题为“万企商服通”的旧 `dist/build/mp-weixin` 窗口显示双胶囊，标题为“WeChat Web Devtools”的当前 `dist/dev/mp-weixin` 窗口显示单胶囊。两个目录的 `app.json` 和页面 JSON 都是 `navigationStyle: default`，说明用户截图不是当前 Vue 页面再次渲染头部，而是旧构建窗口保留的异常模拟器状态。最终处理为保留显式默认导航配置、关闭旧构建窗口，只使用 development 项目继续调试。

## 3. 修改前后的逻辑

### 修改前

八个页面已经移除 `AppHeader`，但最初只删除了原来的 `navigationStyle: custom`；同时微信开发者工具里并存 development 和 build 两个项目窗口，用户继续操作旧 build 窗口时仍会看到异常双胶囊。

### 修改后

首页、服务选择、资料清单、开票、简表、企业资料、消息通知、我的报单及 `globalStyle` 均显式生成：

```json
"navigationStyle": "default"
```

页面内不再绘制标题、返回按钮或胶囊占位；固定标题由 `navigationBarTitleText` 提供，简表页继续通过 `uni.setNavigationBarTitle` 设置具体服务名称。微信开发者工具关闭旧 `dist/build/mp-weixin` 窗口，只保留已接本地接口的 `dist/dev/mp-weixin` 窗口。

## 4. 接口、数据库和前端影响

- 接口：无变化，请求路径、参数、响应和错误码均未改变。
- 数据库：无变化，无表、字段、索引或种子数据调整。
- 前端：只改变小程序页面导航配置；业务表单、路由目标和接口调用不变。
- 配置：没有新增环境变量；开发者工具只保留 `dist/dev/mp-weixin` 项目，避免两个生成目录的窗口混用。

## 5. 目录结构变化

## 7. Bug 定位和回退

- 先检查 `apps/client-uni/src/pages.json` 是否仍为 `navigationStyle: default`。
- 再检查 `apps/client-uni/dist/dev/mp-weixin/app.json` 和对应 `pages/*/*.json` 的生成值。
- 搜索页面是否重新引入 `AppHeader`、自定义胶囊或状态栏占位。
- 微信开发者工具中只打开 `apps/client-uni/dist/dev/mp-weixin`。如果标题为“万企商服通”和“WeChat Web Devtools”的两个窗口同时存在，先关闭旧 build 窗口，再在 development 窗口普通编译。
- 如果所有页面都能显示但任何位置点击都不跳转，检查调试器 WXML 面板左上角的“选择页面元素”按钮；按钮为蓝色时会拦截模拟器点击。本次已明确切换为关闭状态并执行普通编译，生成 WXML 的按钮仍包含 `bindtap`，生成 JS 仍包含 `navigateTo/reLaunch`。
- 回退时恢复 `apps/client-uni/src/pages.json` 和前端规范对应段落即可；不需要回滚接口或数据库。

## 8. 已知限制

- 当前结论针对 development 窗口；CLI 构建和模拟器显示不能代替全部页面的实际返回栈及真机安全区验收。
- `dist/build/mp-weixin` 是生产构建产物，不用于本地接口联调；再次导入它可能重新出现独立窗口和旧模拟器状态。
- 正式环境的 AppID/AppSecret、HTTPS 合法域名、客服配置、真机和生产发布不在本次修复范围内。
