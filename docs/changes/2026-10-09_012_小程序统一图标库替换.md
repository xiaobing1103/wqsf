## 1. 为什么修改

小程序首页、服务选择、资料清单、通知和“我的”等页面混用了字符箭头、CSS 线条和不同风格的图形，图标外观不统一，部分字符还会随系统字体变化。目标是统一使用项目已引入的 `@dcloudio/uni-ui` 图标库，并保持原有业务流程、接口和数据不变。

用户截图中的像素人物属于浏览器批注悬浮层，不在项目 DOM 中，本次没有通过业务 CSS 隐藏外部工具节点。

## 3. 修改前后的逻辑

### 修改前

- 页面分别使用 `→`、`›`、`✓` 字符和 CSS 旋转线条绘制图标。
- 同一类箭头和状态图标在不同页面的粗细、尺寸和对齐方式不一致。
- 直接使用 `uni-icons` 时，项目缺少 SCSS 编译器和可解析的组件类型声明。

### 修改后

```text
页面或通用组件
  -> AppIcon
  -> @dcloudio/uni-ui/uni-icons
  -> 统一的类型、尺寸、颜色和 flex 对齐
```

- 贸易增量、商标咨询和资质申报分别使用 `shop-filled`、`medal-filled` 和 `auth-filled`。
- 页头、底栏、通知、企业、上传、附件、隐私锁、客服和操作按钮统一使用图标库。
- 数字步骤、资料完成度圆环、进度轨道和未读点仍保留，它们属于业务状态，不是装饰图标。
- `sass` 只作为前端构建依赖，不进入业务接口和运行数据。

## 7. Bug 定位和回退

- 图标不显示时先检查 `AppIcon.vue` 的 `type` 是否存在于 `uni-icons`，再检查浏览器控制台和 `uni-ui` 字体资源是否成功加载。
- 构建提示找不到 SCSS 预处理器时检查 `package.json`、`pnpm-lock.yaml` 和本地依赖中的 `sass`。
- TypeScript 无法识别 `uni-icons.vue` 时检查 `src/uni-ui.d.ts` 是否被 `tsconfig.json` 的 `src/**/*.d.ts` 包含。
- 回退时恢复本记录列出的 Vue 文件，删除 `AppIcon.vue` 与 `uni-ui.d.ts`，并移除 `sass`；不需要执行数据库回滚。

## 8. 已知限制

- CLI 构建通过不能替代微信开发者工具和真机对图标字体的最终验收。
- `uni-icons` 当前样式仍触发 Dart Sass legacy JS API 弃用提示，需等待上游构建链升级；本轮没有为了消除提示而改动第三方包。
- 管理后台继续使用现有 `AdminIcon.vue`，没有与小程序共享同一套组件。
