## 1. 为什么修改

后端已经完成本地验收，但管理后台仍把登录、统计、报单、客户和导出内容全部写在单个 `App.vue` 中，并使用固定模拟数据。浏览器没有真实 Token、权限路由和统一错误处理，无法安全地开始前后端联调。

本次只完成第一阶段：后台登录、会话恢复、权限路由和真实工作台汇总。报单、客户、导出页面暂不提前接半套接口，继续保留高保真结构并明确标记为演示数据。

## 3. 修改前后的逻辑

### 修改前

```text
访问后台 -> 直接打开单个 App.vue -> 使用固定模拟数据
          -> 没有登录 -> 没有 Token -> 没有权限判断
```

### 修改后

```text
访问受保护路由
  -> Router 检查 sessionStorage Token
  -> 没有 Token：跳转 /login
  -> 有 Token：GET /auth/me 恢复用户和权限
  -> 检查页面权限
  -> GET /admin/dashboard
  -> 显示真实状态汇总
```

登录流程：

```text
登录表单
  -> POST /auth/admin/login
  -> sessionStorage 保存 Token
  -> GET /auth/me 获取角色和权限
  -> 跳转原目标页面或 /dashboard
```

退出时无论后端是否可连接，都会清除本地会话并回到登录页。

## 4. 接口、数据库和前端影响

- 接口：没有修改后端路径、字段或错误码，只接入已有 `/auth/admin/login`、`/auth/me`、`/auth/logout`、`/admin/dashboard`。
- 数据库：无变化。
- 前端：管理后台从无认证 Mock 页面变成具备真实登录与工作台的 SPA；报单、客户、导出仍为带提示的演示页面。
- 配置：新增 `VITE_API_BASE_URL`。开发环境通过 Vite 代理连接 8080，生产默认要求同源 `/api/v1` 反向代理。
- 安全：Token 只放在当前标签页 `sessionStorage`，不写入普通日志，不在 URL 传递。

## 7. Bug 定位和回退

### 登录打不开或反复跳转

1. 查看 `src/router/index.ts` 的路由守卫。
2. 查看浏览器 `sessionStorage` 是否存在 `wqst_admin_token`。
3. 查看 `src/stores/auth.ts` 的 `restoreSession` 和 `/auth/me` 请求。
4. 后端返回 401 时检查账号、Token 和后端是否重启。

### 登录按钮报网络错误

1. 确认后端 `http://127.0.0.1:8080/actuator/health` 为 `UP`。
2. 确认后台通过 `pnpm dev` 运行在 5174。
3. 查看 `vite.config.ts` 的 `/api` 代理。
4. 查看 `.env.development` 和 `src/api/request.ts`。

### 工作台为 0 或加载失败

1. 查看浏览器 Network 中 `/api/v1/admin/dashboard` 的响应。
2. 查看 `src/api/dashboard.ts` 和 `types/dashboard.ts` 字段是否与后端一致。
3. 数据确实为空时显示 0 是正确行为，不要在前端补模拟数字。

### 回退

代码回退时需要同时恢复 `package.json`、锁文件、Vite 配置、`src` 目录和三份前端文档。回退不会影响数据库和后端。`dist/` 应通过回退后的源码重新构建，不能手工拼接。
