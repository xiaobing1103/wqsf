## 1. 为什么修改

用户点击附件上传时，微信开发者工具报 `An object could not be cloned`。调用栈位于文件选择阶段。模板格式数组来自 Vue/Pinia 响应式状态，直接传入微信桥接导致克隆失败。用户要求区分 H5 与微信并封装成组件供后续复用。

## 3. 修改前后的逻辑

### 修改前

页面接收点击事件，直接将响应式模板格式数组传给 `chooseMessageFile`，微信工具桥接克隆失败。文件尚未选择和上传。

### 修改后

上传卡片 -> FilePicker -> 条件编译的文件选择函数 -> 普通字符串参数 -> 平台选择结果 -> 格式/大小校验 -> 页面业务上传。

H5 使用 chooseFile，微信使用 chooseMessageFile。组件接收剩余数量、扩展名、大小上限与禁用状态，提供 selected/error 事件和按钮插槽。数量已满直接提示，取消静默返回，选择时阻止重复点击。

## 4. 接口、数据库和前端影响

- 接口及数据库：无变化。
- 前端：FileUploadCard 事件从 choose 改为 selected/error，唯一使用页面已同步。
- 配置：无变化；development 与生产构建继续分别使用既有登录模式。

## 5. 目录结构变化

新增 FilePicker.vue，已更新工程导航。生成产物随编译更新，不手工编辑。

## 6. 验证结果

- pnpm typecheck：完整应用和 API 类型检查通过。
- pnpm build:h5、pnpm build:mp-weixin：均输出 DONE Build complete，存在既有 Sass legacy API 弃用警告。
- 内存回归：分别按 H5/MP-WEIXIN 分支转译真实组合函数，以 Vue ref 代理数组作为参数，验证普通化后 structuredClone 成功、选择结果规范化和不允许格式拒绝；均通过。该检查模拟平台调用，不等同于微信原生弹窗验证。
- development 产物已包含 FilePicker 和普通 extension 数组，微信分支不包含 H5 选择调用。
- 未执行后端单元测试、集成测试、容器业务闭环、微信真实文件选择/上传、真机或生产验证。

手工复验：开发者工具普通编译当前 dist/dev/mp-weixin，进入可编辑报单附件页，选择合成 PDF/图片并上传；分别验证取消、超大/不允许格式、数量已满和已提交报单禁用。H5 同步验证本机文件选择和上传。

## 7. Bug 定位和回退

选择报错先看 FilePicker 和 useFileUpload；上传报错看页面、api/upload.ts、Network 与后端文件接口日志。恢复本轮组件和页面改动并重新编译可回退，但直接传响应式参数的问题会恢复。无需数据库回退。

## 8. 已知限制

微信文档选择来自聊天文件；H5 为本机文件选择。组件当前面向附件文档，营业执照照片仍使用既有图片选择入口。构建与模拟参数检查不能替代用户选择文件并成功上传的完整验收。
