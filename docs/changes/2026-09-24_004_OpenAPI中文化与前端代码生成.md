## 1. 为什么修改

原 Swagger 文档使用默认英文标题和 Controller 分组，没有 Bearer Token 定义；Springdoc 对重复方法名自动生成了 `list_1`、`create_1` 等不稳定函数名。前端无法直接把 OpenAPI JSON 当作可靠契约，也没有适配 uni-app 文件上传的生成入口。

本次目标是：

1. 将接口标题、分组、操作摘要、响应说明和主要字段说明统一中文化。
2. 固定稳定的英文 `operationId`，供 Orval 生成可维护的 TypeScript 函数。
3. 在项目根目录提供可重复执行的 JSON 导出、校验和生成命令。
4. 管理后台复用现有 Fetch 请求层，uni-app 使用 `uni.request`；文件上传单独使用 `uni.uploadFile`。
5. 按前端开发者可维护的方式同步更新目录导航、API 规范和变更记录。

## 3. 修改前后的逻辑

### 修改前

```text
Springdoc 默认元数据
  -> 英文标题/默认 Tag/重复方法名自增 operationId
  -> 前端手工维护接口类型
  -> uni-app 文件上传容易误用普通 JSON
```

### 修改后

```text
Controller + OpenApiConfig
  -> 中文 Springdoc 契约 + 稳定 operationId + BearerAuth
  -> pnpm api:export / api:check
  -> openapi/万企商服通_OpenAPI_V1.json
  -> pnpm api:generate
  -> admin-web Fetch 适配器 / uni-app uni.request 适配器
  -> 文件资料使用 uni.uploadFile 专用适配器
```

后端接口路径和统一响应结构没有改动。认证接口的 Java `Map<String,Object>` 仅改为明确 record，登录响应字段仍为 `token`、`tokenType`、`expiresIn`、`user`；当前用户响应仍保留原字段并补充脱敏手机号字段。

## 4. 接口、数据库和前端影响

- 接口：路径不变；OpenAPI 标题从默认值改为 `万企商服通接口文档`，版本为 `1.0.0`；所有操作有稳定 operationId 和中文 summary；增加 BearerAuth 描述。
- 数据库：无表、字段、索引或种子数据变化。
- 管理后台：新增可直接导入的生成 API；原 `apiRequest<T>` 行为不变，生成函数返回完整统一响应包装。适配器会去除契约中的 `/api/v1` 前缀，避免和请求层基础地址重复，并保留 JSON 字符串请求体，不发生二次序列化。
- uni-app：新增生成 API 和 `uni.request` 适配器；文件上传必须调用 `uploadMaterialFile`。
- 配置：新增根目录 Orval 配置；未新增生产密钥或真实客户资料。

## 7. Bug 定位和回退

- Swagger 标题、Tag 或摘要异常：先看 `OpenApiConfig.java` 的 `CONTROLLER_TAGS` 和 `SUMMARIES`。
- 生成函数名变化：检查对应 Controller 名、方法名和 `operationId`，然后重新运行 `pnpm api:sync`。
- 管理后台请求 401/错误处理异常：检查 `apps/admin-web/src/api/request.ts` 的 `rawApiRequest` 和 `generated-client.ts`。
- 小程序普通接口异常：检查 `apps/client-uni/src/api/generated-client.ts` 的 API 基础地址、令牌键和 `uni.request`。
- 上传失败：检查 `apps/client-uni/src/api/upload.ts`、文件字段名 `file`、`caseId`、`materialId` 和后端 `FileController`。
- JSON 与运行中 Swagger 不一致：先重启后端，再执行 `pnpm api:export`；不要手工编辑快照。

回退时保留后端接口路径和 `ApiResponse` 结构，只需删除/恢复本次 generated 目录、脚本和文档；数据库无需回滚。

## 8. 已知限制

1. Swagger UI 自身的按钮文字由第三方界面控制，本次中文化的是接口标题、分组、摘要、响应和字段说明。
2. uni-app 正式微信包仍需在 HBuilderX/DCloud 对应版本编译；当前 `pnpm typecheck` 是生成 API 独立检查，不代表微信包已构建。
3. Orval 生成目录每次会整体重写，任何手工修改都会在下一次生成时丢失。
4. 微信真实登录仍等待正式 AppID/AppSecret；OpenAPI 只保留正式路径和明确的未配置错误。
