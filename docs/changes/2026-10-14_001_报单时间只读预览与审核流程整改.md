## 1. 为什么修改

提交旧草稿时后台按创建日期排列，用户找不到今天的申请；容器 Java 使用 UTC，提交时间与数据库北京时间相差八小时。草稿缺乏保存提示、已提交资料无法点击查看；服务确认页的其他服务容易误切换。后台审核没有显示填写内容，状态下拉立即保存，补件使用固定原因且自动选中全部未通过资料，难以理解并易误操作。

## 3. 修改前后的逻辑

修改前：创建日期被显示成提交日期；状态选择后立即更新；补件包含全部未通过资料；已提交资料入口禁用。

修改后：所有新业务时间使用 Asia/Shanghai；列表按 COALESCE(submitted_at,created_at) 倒序，已提交显示最近提交，草稿标注创建时间。草稿显示创建/最近保存时间并提醒仍需提交审核。提交后的资料可只读查看，不开放写入。首页仍提供其他服务，服务确认页只显示本次服务。

后台流程：查看内容/附件 -> 逐项审核通过 -> 所有必填通过后“审核通过，开始办理” -> 办理后“确认办理完成”。需要补件时勾选具体资料、填写客户可见原因、确认后退回选中项目；其他资料保留。等待客户重新提交后再审核。状态流转具有后端必填审核门槛，不能仅绕过前端按钮。

## 4. 接口、数据库和前端影响

- 列表摘要新增 `submittedAt`；`updatedAt` 汇总报单与资料最近更新时间。
- `/admin/cases/{id}/status` 进入 PROCESSING/COMPLETED 前必填资料需 PASSED/NOT_REQUIRED，否则 409 `CASE_REVIEW_INCOMPLETE`。
- 数据库结构和种子未变，仅修正已有时间；执行前完成全库备份。
- 本地容器配置新增 `TZ=Asia/Shanghai`、`S3_PUBLIC_ENDPOINT=http://127.0.0.1:8333`；内部 S3 地址仍为容器域名。
- 图片/文档预览复用既有权限接口及五分钟签名，不返回永久对象地址，不移除企业范围或敏感权限检查。
