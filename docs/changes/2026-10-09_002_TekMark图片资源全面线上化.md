# TekMark 图片资源全面线上化

> 日期：2026-10-09  
> 序号：002  
> 类型：功能 / 前端静态页面  
> 状态：已完成，待浏览器人工验收

## 1. 为什么要修改

TekMark 名片页原先混用本地图片、字符图标和单个线上 TikTok 图标。根据资源截图，全部图片已经上传到 `https://s3.tkhub.ca/web/assets/email/`，因此将页面中可用的六个图片资源统一切换为线上地址，避免部署 HTML 时还需要携带本地 `img/` 文件。

## 2. 修改文件清单

| 文件 | 类型 | 修改内容 |
| --- | --- | --- |
| `tekmark-card.html` | 修改 | 将顶部图、卡片图、页脚 Logo、Instagram、Facebook 和 TikTok 图标统一替换为线上图片 |
| `docs/03_前端设计与开发规范.md` | 修改 | 更新 TekMark 静态页图片资源规则和资源清单 |
| `docs/changes/README.md` | 修改 | 登记本次变更记录 |

## 3. 修改前后的逻辑

### 修改前

- 顶部图引用 `img/Header.png`。
- 卡片图引用 `img/Frame 2.png`。
- 页脚 Logo 引用 `img/logocom.png`。
- Instagram 和 Facebook 使用字符模拟。
- TikTok 已使用线上 PNG。

### 修改后

所有实际图片统一从 S3 加载：

```text
HeaderImg.png    -> 顶部 Logo 与标语
FrameCardImg.png -> 卡片堆叠展示图
middleImg.png    -> 页脚 Logo
insgramIcon.png  -> Instagram 图标
FacebookIcon.png -> Facebook 图标
TiktokIcon.png   -> TikTok 图标
```

页面不再通过 `<img>` 标签引用本地 `img/` 资源。商务背景图和联系人头像仍是 CSS 占位区，不属于此次提供的六个图片文件。

## 4. 接口、数据库和前端影响

- 接口：无新增、无修改。
- 数据库：无新增、无修改。
- 前端：仅影响根目录 `tekmark-card.html` 的图片加载方式；正式应用路由和状态管理不受影响。
- 外部依赖：页面图片显示依赖 `https://s3.tkhub.ca/web/assets/email/` 可访问。

## 5. 目录结构变化

无新增、删除或移动目录和关键文件。本地 `img/` 文件未删除，可继续作为备份。

## 6. 验证结果

- 静态检查：六个预期线上地址均已写入 HTML，旧的三个本地 `<img>` 路径及 Instagram、Facebook 字符图标均已移除。
- 网络检查：`FacebookIcon.png`、`FrameCardImg.png`、`HeaderImg.png`、`insgramIcon.png`、`middleImg.png`、`TiktokIcon.png` 均返回 HTTP 200。
- 未执行浏览器人工视觉验收、单元测试、集成测试、容器实跑或生产验证。

## 7. Bug 定位和回退

- 图片不显示：先在浏览器网络面板检查对应 S3 地址和跨域/网络状态，再检查 `tekmark-card.html` 中的 `src`。
- 图标尺寸异常：检查 `.socials img` 的 16×16 像素样式。
- 回退方式：将顶部、卡片和页脚图片恢复为本地相对路径，将社交图标恢复为本地文件或原字符；不涉及后端和数据库。

## 8. 已知限制

- 线上资源可用性依赖外部 S3 服务。
- `insgramIcon.png` 文件名按服务器现有拼写使用，不能自行改成 `InstagramIcon.png`。
- 社交平台主页跳转地址仍未提供，本次只替换图标图片。
