## 3. 主要业务逻辑

```text
客户登录
  -> 选择企业和服务
  -> 创建报单草稿并生成资料快照
  -> 填写开票/简表单、上传文件
  -> 提交待审核
  -> 后台逐项审核或发起补件
  -> 客户补件并重新提交
  -> 后台处理中、完成
  -> 按权限导出 Excel 或 ZIP
```

关键规则：

- 贸易增量创建 11 项资料；知识产权和资质申报创建 3 项基础资料。
- 报单状态只能通过 `CaseStateMachine` 规定的路线流转。
- 客户访问同时检查登录、角色权限和企业成员关系。
- 敏感文件预览和敏感 ZIP 创建/下载都需要独立权限并写日志。
- Excel 导入和导出使用异步任务，使用数据库条件抢占防止重复执行。
- 手机号、税号和基本户账号使用加密值、摘要值和掩码值分开保存。

## 4. Review 中修复的问题

- 生产配置重复 `wqst` 顶层键。
- 后台预览非敏感文件缺少 `case:view` 检查。
- 客户端创建报单缺少 `case:create` 权限检查。
- 客户端 Sa-Token 登录场景未参与角色权限读取。
- 敏感 ZIP 下载没有再次检查敏感文件权限。
- 系统文件可能进入客户端删除逻辑。
- 导入模板和错误报告写库失败后的对象存储补偿不完整。
- 文档索引仍把已完成后端描述为模拟骨架。
- Testcontainers 只有依赖没有测试类，现已补充真实集成测试代码。

## 5. 接口、数据库和前端影响

- 正式接口统一为 `/api/v1`，旧模拟接口已删除。
- 前端需要按照 `docs/04_API接口设计.md` 联调，不再依赖旧 `/api/cases`。
- 客户端 Token 和后台 Token 属于两个 Sa-Token 登录场景，不能混用。
- 创建、提交、补件、导入和导出必须传 `Idempotency-Key`。
- 数据库目标为 26 张业务表，静态种子为 3/3/3/17。
- 微信真实登录尚未启用，本地只能使用 `dev-login`。

## 8. Bug 定位和回退

- 接口字段或错误码问题：先看对应 Controller、Service 和 `docs/04_API接口设计.md`。
- 报单状态问题：看 `CaseStateMachine.java` 和 `CaseService.java`。
- 文件问题：看 `FileInspector.java`、`FileService.java` 和 SeaweedFS 日志。
- 导入导出问题：看对应 Worker、Recovery 和任务表状态。
- 登录权限问题：看 `AuthService.java`、`SaTokenPermissionProvider.java` 和权限种子。
- 数据库初始化问题：不要删除旧 Volume；先在空开发库验证 001、002。

如果需要整体回退，应同时回退 Java 代码、SQL、Compose 和接口文档；不能只回退前端字段。
