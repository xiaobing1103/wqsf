## 1. 为什么修改

管理后台侧边栏的“团队与权限”原来只有提示信息，没有真实路由和页面；客户资料列表最后一列使用不可点击的三个点文本，无法新增、查看、编辑或删除企业。后端已有账号列表、账号创建和角色分配接口，但企业只实现列表、新增和成员绑定，无法支撑完整维护流程。

本次目标是使用现有角色模型补齐团队页面，并为企业客户增加安全的查询、编辑和软删除能力。实现继续遵循最小权限、敏感字段不回显和历史数据不物理删除原则。

## 3. 修改前后的逻辑

### 修改前

```text
团队与权限 -> 点击只显示提示
客户三点 -> 普通文本，不能操作
企业接口 -> 只有列表、新增、绑定成员
```

### 修改后

```text
超级管理员 -> /team
  -> 查看后台成员
  -> 创建后台账号
  -> 调整 OPERATIONS / REVIEWER / SUPER_ADMIN
  -> 查看后端返回的实际权限

客户资料 -> 三点菜单
  -> 查看脱敏详情
  -> 编辑非敏感字段，敏感字段留空保持原值
  -> 超级管理员二次确认软删除
     -> 检查 version
     -> 检查不存在未完成报单
     -> 企业和成员关系停用
     -> 保留报单、文件和审计日志
```

## 4. 接口、数据库和前端影响

- 接口：新增 `GET /api/v1/admin/companies/{companyId}`、`PATCH /api/v1/admin/companies/{companyId}` 和 `DELETE /api/v1/admin/companies/{companyId}?version=...`。
- 错误码：删除存在未完成报单的企业返回 `COMPANY_ACTIVE_CASE_EXISTS`；版本过期返回已有的 `OPTIMISTIC_LOCK_CONFLICT`。
- 数据库：没有新增或修改表、字段、索引、迁移和种子数据；删除复用 `company.deleted_at`、`status` 和 `company_user.status`。
- 前端：新增 `/team`；客户列表三点图标变为操作菜单，新增客户、详情、编辑和软删除均接真实接口。
- 权限：团队页面和账号接口仅超级管理员；企业删除仅超级管理员，列表、新增和编辑沿用 `company:view`。
- 敏感信息：信用代码和联系电话仅返回掩码；编辑留空时不覆盖原值，页面不保存明文历史值。
- 配置：无新增环境变量。

## 7. Bug 定位和回退

- 团队页面不显示：先看 `router/index.ts` 的 `SUPER_ADMIN` 守卫、`stores/auth.ts` 的 `hasRole` 和 `/auth/me` 返回角色。
- 团队接口 403：检查 `AdminAccountController` 的 `@SaCheckRole("SUPER_ADMIN")` 和账号 `user_role` 数据。
- 客户三点菜单不出现：检查 `AdminLayout.vue` 的 `companyMenuId` 和 `styles.css` 的 `.action-menu` 层级。
- 编辑返回冲突：重新请求企业详情取得最新 `version`，不要在前端强行覆盖。
- 删除被拒绝：根据 `COMPANY_ACTIVE_CASE_EXISTS` 检查该企业是否仍有非 `COMPLETED/CANCELED` 报单。
- 回退时恢复上述前后端文件和 OpenAPI 生成结果；数据库没有迁移，不需要执行回退 SQL。已经软删除的数据不会因代码回退自动恢复，需经确认后单独恢复企业及成员状态。

## 8. 已知限制

- 后端尚未提供账号停用、账号删除和密码重置接口，团队页面没有提供这些操作。
- 当前只使用三个固定后台岗位，不支持在页面自定义角色或逐项勾选权限。
- 浏览器自动点击验收需要管理员重新登录后执行，本轮未获取、输入或绕过用户密码。
- 小程序、微信真实登录、真机和生产环境未验证。
