## 1. 为什么修改

Windows 重启后需要完成之前未执行的 Docker、空库和 Testcontainers 验收。真实运行过程中发现四个问题：

1. Docker Desktop 首次启动误判 WSL 未安装。
2. MySQL 8.4 将 `row_number` 识别为保留语法，`002_full_schema.sql` 初始化中断。
3. SeaweedFS 4.06 已删除健康检查使用的 `-server`、`-command` 参数。
4. MyBatis Mapper 扫描路径包含无效的 `**`，导致应用上下文找不到部分 Mapper；集成测试也没有启用本地模拟客户初始化。

目标是修复上述问题，并让容器、空库、单元测试、集成测试和本机接口烟测全部得到真实结果。

## 7. Bug 定位和回退

### Bug 定位

- SQL 初始化失败：先看 `docker compose logs mysql`，再按报错行检查 `database/002_full_schema.sql`。
- SeaweedFS 长期 `starting`：执行 `docker inspect wqst-seaweedfs` 查看 `State.Health.Log`。
- Spring 报 `NoSuchBeanDefinitionException` 且类型为 Mapper：检查 `MybatisConfig` 和接口上的 `@Mapper`。
- `BUILD SUCCESS` 但集成测试跳过：检查 `target/failsafe-reports`，确认 `Skipped: 0`；Docker 400 时检查 API 1.40 参数。
- 开发客户登录 404：确认当前是 `local` Profile，且日志中没有本地模拟数据初始化失败。

### 回退

- 代码回退需同时恢复 SQL 字段、实体映射、健康检查、Mapper 扫描和测试 Profile。
- 如果开发库已按 `row_no` 创建，回退 SQL 前必须先迁移字段，不能只回退 Java 实体。
- 不要删除原有 `mysql`、`valkey`、`seaweedfs` Volume；需要重建时只操作已核对标签的本项目开发卷。
