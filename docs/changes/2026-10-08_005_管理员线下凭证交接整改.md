## 1. 为什么修改

网银 U 盾、登录密码、交易密码和短信验证码属于认证秘密，不能让客户在小程序中提交，也不能进入普通业务数据库、日志、导出或文件存储。本次把需求收敛为“管理员记录线下实物和凭证的交接状态”，并为企业提供不含密码项的统一 Excel 信息表。

## 3. 修改前后的逻辑

### 修改前

- 系统没有专门的线下凭证交接模型和接口。
- 如果直接照原始清单收集，存在把网银密码、U 盾密码或交易密码上传到小程序或数据库的风险。
- 管理后台无法区分某项凭证是待交接、已交接、已核验还是已归还。

### 修改后

```text
管理员打开贸易增量报单详情
  -> 后台读取线下凭证交接状态
  -> 管理员只选择三类凭证的状态
  -> 后端校验权限、报单类型和乐观锁
  -> 数据库只保存状态、经办人、时间和版本
```

密码、验证码、密钥文件和自由备注不进入该流程。企业需要提交的非秘密资料统一通过安全版 Excel 或既有资料上传流程收集。

## 4. 接口、数据库和前端影响

- 接口：新增 `GET/PUT /api/v1/admin/cases/{caseId}/credential-handover`；其他路径、响应和错误码不变。
- 数据库：新增 `credential_handover` 表和 `case:credential-handover` 权限，角色 `SUPER_ADMIN`、`OPERATIONS`、`REVIEWER` 获得该权限。
- 前端：仅管理后台贸易增量报单详情新增交接面板；小程序不展示、不调用该能力。
- 配置：Compose 新增 003 初始化脚本挂载，没有新增环境变量。

## 7. Bug 定位和回退

- 面板不显示：先检查报单是否为贸易增量、当前管理员是否有 `case:credential-handover` 权限，再看 `AdminLayout.vue` 的权限判断。
- 查询或保存失败：先看 `AdminCaseController`、`CredentialHandoverService` 和后端日志；409 优先检查页面 `version` 是否过期。
- 数据库报表不存在：检查 003 脚本是否执行、Compose 初始化挂载和 `credential_handover` 表。
- 回退代码时需同时移除前端面板、两个接口、Service/Entity/Mapper、生成契约和权限引用；数据库迁移应单独评估数据保留后再删除表和权限，不能直接覆盖现有库。

## 8. 已知限制

- 浏览器自动化点击验收未执行，仍建议人工按“报单管理 → 贸易增量报单详情 → 线下凭证交接”完成一次保存和刷新检查。
- 未部署生产环境，未验证生产权限、网关、审计和备份策略。
- 当前只记录交接状态，不承担密码保险库能力；未来如确需电子托管，必须接入独立的企业级密钥保险库并另行安全评审。
