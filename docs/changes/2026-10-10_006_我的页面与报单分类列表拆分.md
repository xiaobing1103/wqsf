## 1. 为什么修改

原“我的报单”页面同时放置企业身份、四项统计、完整分页报单和账号功能，页面过长，四项统计数字也不能点击。用户希望“我的”主要展示企业资料，报单列表不再直接铺在该页面；全部报单、处理中、待补资料、已完成需要作为独立入口，并能继续打开具体报单查看资料状态。

## 3. 修改前后的逻辑

### 修改前

```text
我的页面
  -> 企业/用户卡片
  -> 只显示数字的四项统计
  -> 页面内直接渲染全部报单并分页
  -> 企业、消息、客服、账号入口
```

“处理中”数字由前端分别请求 `PENDING_REVIEW` 和 `PROCESSING` 后相加；如果直接在新列表中拼接两套分页数据，会出现页大小和全局排序不一致。

### 修改后

```text
我的页面
  -> 当前企业资料
  -> 点击全部/处理中/待补资料/已完成
  -> 独立报单列表（服务端统一分页）
  -> 点击报单
  -> 贸易资料清单或商标/资质简表
  -> 查看资料完成度、状态和补件要求
```

处理中列表向既有接口传 `status=PENDING_REVIEW,PROCESSING`，后端在同一个数据库查询中使用 `IN` 筛选并按创建时间倒序分页。

## 4. 接口、数据库和前端影响

- 接口：`GET /api/v1/cases/my` 的路径、响应和错误码不变；`status` 从单状态扩展为兼容英文逗号分隔的多状态，单状态调用继续兼容。
- 数据库：无表、字段、索引、迁移和种子数据变化。
- 前端：新增 `/pages/case/list?filter=all|processing|supplement|completed`；“我的”不再加载或显示报单卡片，首页和提交成功跳转同步调整。
- 配置：无新增环境变量或构建配置。

## 7. Bug 定位和回退

- 数量或分类错误：先查 `mine/index.vue` 的统计请求、`case/list.vue` 的筛选映射和 `CaseService.statusFilter/mine`。
- 列表能显示但详情打不开：检查 `constants/service.ts` 的 `caseDetailRoute` 和接口返回的 `serviceType`。
- 提交成功仍回到“我的”：检查 `materials.vue`、`simple.vue` 的成功跳转是否指向 `filter=processing`。
- 回退时恢复本记录列出的业务代码和维护文档，删除新增列表页并重新构建；没有数据库变更，不需要数据库回滚。

## 8. 已知限制

- 报单详情继续复用现有贸易资料清单和商标/资质简表，统一的报单时间线页面尚未实现。
