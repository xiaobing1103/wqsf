## 1. 为什么修改

小程序“企业资料”“消息通知”和“联系客服”原来没有真实业务入口，M05 商标注册咨询与资质申报服务也只有占位页，无法形成可交付的客户流程。本次目标是在不新增敏感字段、不修改既有数据库的前提下，复用后端现有企业、通知和简表报单能力完成接入。

## 3. 修改前后的逻辑

### 修改前

- 企业资料没有点击行为。
- 首页和“我的”的消息入口只显示后续接入提示。
- 联系客服只显示笼统 Toast。
- 商标与资质服务进入 M05 占位页，不能创建或提交报单。
- M06 所有报单统一打开贸易增量资料页，简表报单路由错误。

### 修改后

```text
企业资料 -> /companies/my -> 脱敏资料页
消息通知 -> /notifications/my -> 标记已读 -> 按 serviceType 打开关联报单
商标/资质 -> 创建或恢复草稿 -> 保存三字段简表 -> 提交审核 -> M06
联系客服 -> 微信原生客服会话；H5 显示平台边界提示
```

简表只包含法人姓名、公司名称和联系电话。联系电话由后端加密保存，重新打开只显示掩码；页面不提供征信、网银、U 盾、交易密码、验证码或开票字段。

## 4. 接口、数据库和前端影响

- 接口：没有新增或修改后端契约，复用 `/companies/my`、`/notifications/my`、`/notifications/{id}/read`、`/cases`、`/cases/{id}/simple-info` 和 `/cases/{id}/submit`。
- 数据库：没有表、字段、索引或种子变更；复用 `notification`、`IP_SIMPLE` 和 `QUALIFICATION_SIMPLE`。
- 前端：新增企业资料、通知中心页面和通知 API；M05 从占位页升级为真实流程；M06 报单跳转按服务类型分流。
- 配置：没有新增环境变量。微信客服依赖正式小程序公众平台配置客服人员。

## 7. Bug 定位和回退

- 企业资料异常先看 `pages/company/profile.vue`、`stores/company.ts` 和 `/companies/my`。
- 通知异常先看 `pages/notification/index.vue`、`api/notification.ts`、`NotificationController` 和 `notification` 表。
- 简表创建或提交异常先看 `pages/service/simple.vue`、`stores/caseDraft.ts`、`api/case.ts` 和后端 `CaseService.saveSimple/submit`。
- 服务跳转错误先看 `constants/service.ts` 的 `serviceType` 与 `caseDetailRoute`。
- 回退时删除三个新增文件，并恢复本次修改的路由、入口、Store、API 和文档；不需要执行数据库回滚。
