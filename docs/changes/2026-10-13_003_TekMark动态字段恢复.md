## 3. 修改前后的逻辑

### 修改前

当前工作区没有模板文件。上一版仅保留 `{{ owner.first_name }}`、`{{ owner.full_name }}` 和 `{{ owner.job_title }}`，背景和头像为静态占位，两个个人链接为页面锚点。

### 修改后

恢复七个同风格的双大括号变量：

| 用途 | 模板字段 | HTML 位置 |
| --- | --- | --- |
| 名字、全名、职位 | `owner.first_name`、`owner.full_name`、`owner.job_title` | 文案 |
| 背景图 | `owner.background_image_url` | 背景 `<img src>` |
| 头像 | `owner.avatar_url` | 头像 `<img src>` |
| 完整资料页 | `owner.profile_url` | 主按钮 `<a href>` |
| 联系人名片 | `owner.vcard_url` | vCard 链接 `<a href>` |

头像与姓名仍分属连续表格行，避免邮件客户端出现遮挡。静态品牌图和商城、政策页链接保留原有地址。

## 4. 接口、数据库和前端影响

- 接口：仓库内未修改后端接口；发信渲染数据需包含上述四个动态资源或链接。如果请求使用 `owner.background_url`，需映射为模板中的 `owner.background_image_url`。

## 7. Bug 定位和回退

- 图片或链接仍未替换：检查发信服务传给模板引擎的对象键名与双大括号语法；特别检查 `background_url` 到 `background_image_url` 的映射。
- 收件人收到旧版：检查发信平台模板缓存与实际模板来源，重新上传当前 HTML。
- 头像遮挡姓名：检查发信平台是否在变量替换外又注入绝对定位样式。
- 回退方式：恢复上一版模板和对应文档；不涉及数据库回滚。
