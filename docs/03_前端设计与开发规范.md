# 万企商服通前端设计与开发规范

> 客户端：uni-app + Vue 3 + TypeScript + Pinia  
> 管理后台：Vue 3 + Vite + TypeScript + Pinia + Vue Router

## 1. 前端范围

前端包含两个运行端：

- `apps/client-uni`：微信小程序客户端，同时保留 H5 调试能力。
- `apps/admin-web`：运营和审核后台，桌面端优先。

`apps/design-preview` 仅用于高保真评审、截图和 PDF 生成，不承载正式业务逻辑，不作为生产页面入口。

## 2. 共同原则

- 页面负责组合和交互，业务规则放在 composable、store 或 API 层。
- 所有接口调用集中管理，页面不得直接拼接 URL。
- 所有状态文字、颜色和按钮权限使用统一字典。
- 所有表单都有加载、校验、提交中、成功和失败状态。
- 不使用真实客户敏感数据作为 Mock 数据。
- TypeScript 类型优先，禁止无说明地使用 `any`。
- 组件优先使用小而清晰的单一职责组件。

## 4. 命名规范

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 页面文件 | 小写目录 + `index.vue` 或语义名称 | `case/materials.vue` |
| 组件 | PascalCase | `FileUploadCard.vue` |
| Composable | `use` + PascalCase | `useFileUpload.ts` |
| Store | `use` + 名称 + `Store` | `useCaseDraftStore` |
| 类型 | PascalCase | `CaseDetail` |
| 常量 | UPPER_SNAKE_CASE | `CASE_STATUS_LABEL` |
| 事件 | `on` + 动作 | `onSubmit` |
| Props | 名词，不使用缩写 | `materialItem` |

组件事件统一使用 `update:modelValue`、`submit`、`retry`、`preview` 等语义名称，不使用 `click1`、`handleData`。

## 6. API 请求层

统一封装：

```ts
export type ApiResponse<T> = {
  success: boolean
  code: string
  message: string
  data: T
  requestId: string
}
```

请求层负责：

- 拼接 API 基础地址。
- 自动注入 Authorization。
- 统一处理 401、403、429 和网络错误。
- 自动附加 `X-Request-Id` 和可选 `Idempotency-Key`。
- 取消重复请求或让页面明确处理竞态。
- 不在全局拦截器里弹出所有错误；业务页面决定是否展示 Toast、表单错误或空状态。

页面只能调用 `api/case.ts` 等领域 API，不直接调用 `uni.request` 或 `fetch`。

## 7. Pinia 状态规范

### 7.1 全局状态

只保存跨页面真正需要的状态：

- 当前用户和令牌。
- 当前企业列表及选中企业。
- 产品目录短缓存。
- 后台用户权限集合。

### 7.2 页面状态

列表分页、筛选条件、弹窗开关和临时表单值优先留在页面或 composable，不要全部塞进全局 Store。

### 7.3 草稿状态

贸易增量草稿使用 `useCaseDraftStore`：

- 以 `caseId` 为键。
- 保存文本字段和已上传文件元数据，不保存文件二进制。
- 本地缓存只保存脱敏字段和草稿版本。
- 提交成功或用户主动删除后清理本地草稿。
- 服务端草稿为最终来源，发生版本冲突时提示用户选择刷新或覆盖。

## 8. 小程序表单规范

### 8.1 M04 开票信息

统一字段：

```text
companyName
taxNo
contactAddress
contactPhone
legalPerson
companyEmail
bankBranch
basicAccount
```

校验规则：

- 公司名称必填，长度 2–128。
- 税号按后端规则校验，前端只做基础长度和字符提示。
- 联系电话必须是合法手机号或后端允许的企业座机格式。
- 公司邮箱使用标准邮箱格式。
- 基本户账号只允许数字和空格输入，提交前去除空格并交给后端校验。

前端显示基本户账号和税号时默认掩码，编辑时按权限和业务需要显示，不把完整值写入埋点。

### 8.2 M05 简表单

只显示：

- 法人姓名。
- 公司名称。
- 联系电话。

不加载贸易增量资料，不显示征信、网银或开票相关控件。

### 8.3 必填和错误提示

- 必填标记使用统一样式。
- 错误提示靠近字段，不只使用顶部 Toast。
- 服务端校验错误映射到字段时保留用户已填写内容。
- 提交按钮在请求期间禁用，并显示明确的提交中状态。

## 9. 文件上传规范

### 9.1 `FileUploadCard` 状态

```text
idle       未上传
selecting  选择中
uploading  上传中
success    已上传
failed     上传失败，可重试
deleting   删除中
```

状态必须有文字，不得只通过颜色表达。

### 9.2 上传流程

1. 根据资料模板读取允许格式、大小和数量。
2. 客户选择文件。
3. 前端先做大小和扩展名预检。
4. 调用上传 API，展示百分比或阶段进度。
5. 成功后保存后端返回的 `fileId`，不保存永久 URL。
6. 失败显示原因并允许单项重试。
7. 删除文件需要二次确认，并调用后端删除/标记接口。

### 9.3 前端安全

- 不信任客户端 MIME 和扩展名，后端必须再次校验。
- 不在日志、埋点和错误上报中上传文件内容。
- 不把身份证、征信、网银截图转成 Base64 放入 Store 或 localStorage。
- 预览链接只放在组件短生命周期内，关闭弹窗后清空。

## 11. M01–M06 实现规范

### M01 首页

- 首屏显示三类服务入口。
- 当前报单卡片支持空数据。
- 读取企业和当前报单接口失败时显示可重试状态。

### M02 服务选择

- 服务卡片只允许选择已上架服务。
- 显示资料数量、办理方式和隐私提示。
- 选择后根据 `serviceType` 跳转 M03 或 M05。

### M03 贸易增量清单

- 11 项由后端模板返回，不在前端硬编码业务数量。
- 已上传、待补充、待审核分别展示状态。
- 提交前重新拉取资料项，防止页面停留期间状态过期。

### M04 开票与附件

- 开票信息使用结构化表单。
- 附件按资料项分组上传。
- 上传失败只影响当前文件，不阻塞已成功资料。

### M05 简表单

- 只渲染后端返回的 3 项字段。
- 显示协议勾选状态。
- 成功提交后进入报单详情或 M06。

### M06 我的报单

- 报单列表支持分页或按需加载。
- 卡片显示状态、完成度和补件说明。
- 无报单、无更多数据和接口异常使用不同状态。

## 12. 管理后台规范

### B01 工作台

- 指标卡只展示聚合数字。
- 趋势图数据由接口返回，不在组件内生成业务数字。
- 关注事项可跳转对应报单。

### B02 报单管理

- 筛选条件与 URL query 同步，便于刷新和复制链接。
- 列表分页默认 `pageSize=20`，最大不超过 100。
- 批量操作必须有权限、二次确认和结果反馈。

### B03 产品管理

- 模板发布后不可直接修改，编辑创建新草稿版本。
- 下架保留历史报单引用。
- 新建和上下架动作需要操作日志。

### B04 客户资料

- Excel 审核表和 ZIP 原始资料使用两个明确按钮。
- ZIP 按钮只在用户拥有 `export:zip` 时显示或可用。
- Excel 导出不得带敏感原件。

### B05 逐项审核

- 客户可见说明和内部备注必须分离组件和类型。
- 敏感预览按钮需要额外权限。
- 审核结果保存成功后刷新当前资料项和报单状态。

### B06 导出中心

- 导出任务显示 `PENDING/RUNNING/SUCCEEDED/FAILED/EXPIRED`。
- 轮询间隔建议 2 秒，页面离开后停止轮询。
- 下载前再次检查任务权限和有效期。

## 13. Excel 导入前端规范

导入流程必须包含：

1. 下载模板。
2. 选择或拖放文件。
3. 解析中进度。
4. 预览总行数和错误行数。
5. 确认导入。
6. 查看成功、跳过和失败报告。

拖放区域仅用于后台 Web，不在微信小程序端实现拖放；小程序使用选择文件/图片能力。

错误报告中手机号、税号和账号必须掩码。

### 18.2 当前路由

```text
/login       后台登录
/dashboard   工作台，需要 dashboard:view
/cases       报单保留页面，需要 case:view
/companies   客户保留页面，需要 company:view
/exports     导出保留页面，需要 export:excel

/forbidden   无权限页面
```

路由守卫负责恢复会话和页面级权限。后端仍负责最终权限判断，前端隐藏或拦截不能代替后端权限。

### 18.3 Token 和请求规则

- 后台 Token 只保存在当前标签页的 `sessionStorage`，键名为 `wqst_admin_token`。
- 请求层自动增加 `Authorization: Bearer <token>` 和 `X-Request-Id`。
- 401 会清理 Token，并返回登录页；登录接口自身的 401 只显示“用户名或密码错误”。
- 网络不可达、非 JSON 响应和业务错误统一转换为 `ApiError`。
- 开发环境请求 `/api/v1`，由 Vite 代理到 `http://127.0.0.1:8080`。
- 生产环境默认使用同源 `/api/v1`，部署时需要由网关反向代理到后端。

### 18.4 工作台数据边界

工作台汇总接口返回启用企业数、报单状态数量、待处理导入任务数和待处理导出任务数；最近报单区域另外调用 `GET /api/v1/admin/cases?page=1&pageSize=5`。接口没有返回的趋势和同比数据不允许由前端虚构。

### 18.5 检查命令

```powershell

```

`pnpm check` 会先执行 `vue-tsc --noEmit`，再执行 Vite 生产构建。只执行 `pnpm build` 不能代替完整 TypeScript 检查。

## 19. OpenAPI 生成 API 规范

前端接口类型以根目录 `openapi/万企商服通_OpenAPI_V1.json` 为唯一契约来源，不在页面中手写重复的请求和响应类型。生成命令为：

```powershell
cd C:\Users\Administrator\Desktop\shopify\wqsf
pnpm api:sync

cd apps/admin-web
pnpm check

cd ../client-uni
pnpm typecheck       # 校验生成 API、models 和两个请求适配器
```

生成结果位于：

```text
apps/admin-web/src/api/generated/
apps/client-uni/src/api/generated/
```

这些目录带有 `Do not edit manually` 标记。需要修改接口时修改后端 Controller/record 和 `OpenApiConfig`，重新导出并生成；不要直接改生成文件。

### 19.1 管理后台适配器

`apps/admin-web/src/api/generated-client.ts` 调用 `api/request.ts` 的 `rawApiRequest`，返回完整 `ApiResponse<T>`，因此保留统一错误、401 跳转、Token 和 Request ID 行为。已有页面使用 `apiRequest<T>`，继续得到解包后的 `data`。

页面不得直接调用生成目录。后台领域适配层位于 `apps/admin-web/src/api/{cases,companies,catalog,exports}.ts`，统一通过 `unwrap.ts` 取出业务数据；页面只管理加载、空数据、错误、分页和操作状态。生成目录重新生成后先检查这些适配层的模型导入，再运行 `pnpm check`。

### 19.2 uni-app 适配器和文件上传

`apps/client-uni/src/api/generated-client.ts` 将生成函数转换为 `uni.request`，默认从 `wqst_client_token` 读取令牌。文件、视频和图片不通过 JSON 发送：使用 `apps/client-uni/src/api/upload.ts` 的 `uploadMaterialFile`，由 `uni.uploadFile` 发送 multipart 请求并返回后端 `data`。

### 19.3 生成代码的边界

- 生成 API 是接口调用层，不包含页面状态、Toast、表单校验或权限按钮逻辑。
- `operationId` 是生成函数名契约，修改它会造成前端函数名变化，必须在变更记录中说明。
- 后端统一响应包装不会被删除；新增字段优先向后兼容。
- 正式微信包仍使用 HBuilderX/DCloud 编译链；当前 `client-uni` 的 `pnpm typecheck` 只校验生成 API 和适配器，避免把版本不匹配的 DCloud 声明误认为业务代码错误。
