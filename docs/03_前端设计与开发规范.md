# 万企商服通前端设计与开发规范

> 客户端：uni-app + Vue 3 + TypeScript + Pinia  
> 管理后台：Vue 3 + Vite + TypeScript + Pinia + Vue Router

## 1. 前端范围

前端包含两个运行端：

- `apps/client-uni`：微信小程序客户端，同时保留 H5 调试能力。
- `apps/admin-web`：运营和审核后台，桌面端优先。

`apps/design-preview` 仅用于高保真评审、截图和 PDF 生成，不承载正式业务逻辑，不作为生产页面入口。

## 2. 共同原则

- 页面负责组合和交互，业务规则放在 composable、store 或 API 层。
- 所有接口调用集中管理，页面不得直接拼接 URL。
- 所有状态文字、颜色和按钮权限使用统一字典。
- 所有表单都有加载、校验、提交中、成功和失败状态。
- 不使用真实客户敏感数据作为 Mock 数据。
- TypeScript 类型优先，禁止无说明地使用 `any`。
- 组件优先使用小而清晰的单一职责组件。

## 4. 命名规范

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 页面文件 | 小写目录 + `index.vue` 或语义名称 | `case/materials.vue` |
| 组件 | PascalCase | `FileUploadCard.vue` |
| Composable | `use` + PascalCase | `useFileUpload.ts` |
| Store | `use` + 名称 + `Store` | `useCaseDraftStore` |
| 类型 | PascalCase | `CaseDetail` |
| 常量 | UPPER_SNAKE_CASE | `CASE_STATUS_LABEL` |
| 事件 | `on` + 动作 | `onSubmit` |
| Props | 名词，不使用缩写 | `materialItem` |

组件事件统一使用 `update:modelValue`、`submit`、`retry`、`preview` 等语义名称，不使用 `click1`、`handleData`。

## 6. API 请求层

统一封装：

```ts
export type ApiResponse<T> = {
  success: boolean
  code: string
  message: string
  data: T
  requestId: string
}
```

请求层负责：

- 拼接 API 基础地址。
- 自动注入 Authorization。
- 统一处理 401、403、429 和网络错误。
- 自动附加 `X-Request-Id` 和可选 `Idempotency-Key`。
- 取消重复请求或让页面明确处理竞态。
- 不在全局拦截器里弹出所有错误；业务页面决定是否展示 Toast、表单错误或空状态。

页面只能调用 `api/case.ts` 等领域 API，不直接调用 `uni.request` 或 `fetch`。

## 7. Pinia 状态规范

### 7.1 全局状态

只保存跨页面真正需要的状态：

- 当前用户和令牌。
- 当前企业列表及选中企业。
- 产品目录短缓存。
- 后台用户权限集合。

### 7.2 页面状态

列表分页、筛选条件、弹窗开关和临时表单值优先留在页面或 composable，不要全部塞进全局 Store。

### 7.3 草稿状态

贸易增量草稿使用 `useCaseDraftStore`：

- 以 `caseId` 为键。
- 保存文本字段和已上传文件元数据，不保存文件二进制。
- 本地缓存只保存脱敏字段和草稿版本。
- 提交成功或用户主动删除后清理本地草稿。
- 服务端草稿为最终来源，发生版本冲突时提示用户选择刷新或覆盖。

## 8. 小程序表单规范

### 8.1 M04 开票信息

统一字段：

```text
companyName
taxNo
contactAddress
contactPhone
legalPerson
companyEmail
bankBranch
basicAccount
```

校验规则：

- 公司名称必填，长度 2–128。
- 税号按后端规则校验，前端只做基础长度和字符提示。
- 联系电话必须是合法手机号或后端允许的企业座机格式。
- 公司邮箱使用标准邮箱格式。
- 基本户账号只允许数字和空格输入，提交前去除空格并交给后端校验。

前端显示基本户账号和税号时默认掩码，编辑时按权限和业务需要显示，不把完整值写入埋点。

### 8.2 M05 简表单

只显示：

- 法人姓名。
- 公司名称。
- 联系电话。

不加载贸易增量资料，不显示征信、网银或开票相关控件。

页面按企业、产品和服务类型恢复可编辑草稿；没有草稿时通过 `Idempotency-Key` 创建。联系电话保存后只显示后端掩码，用户修改姓名或公司名称时需要重新输入联系电话，避免把掩码当成原值提交。提交前必须勾选资料使用授权，保存简表成功后再调用报单提交接口。

### 8.3 必填和错误提示

- 必填标记使用统一样式。
- 错误提示靠近字段，不只使用顶部 Toast。
- 服务端校验错误映射到字段时保留用户已填写内容。
- 提交按钮在请求期间禁用，并显示明确的提交中状态。

## 9. 文件上传规范

### 9.1 `FileUploadCard` 状态

```text
idle       未上传
selecting  选择中
uploading  上传中
success    已上传
failed     上传失败，可重试
deleting   删除中
```

状态必须有文字，不得只通过颜色表达。

### 9.2 上传流程

1. 根据资料模板读取允许格式、大小和数量。
2. 客户选择文件。
3. 前端先做大小和扩展名预检。
4. 调用上传 API，展示百分比或阶段进度。
5. 成功后保存后端返回的 `fileId`，不保存永久 URL。
6. 失败显示原因并允许单项重试。
7. 删除文件需要二次确认，并调用后端删除/标记接口。

### 9.3 前端安全

- 不信任客户端 MIME 和扩展名，后端必须再次校验。
- 不在日志、埋点和错误上报中上传文件内容。
- 不把身份证、征信、网银截图转成 Base64 放入 Store 或 localStorage。
- 预览链接只放在组件短生命周期内，关闭弹窗后清空。

## 11. M01–M06 实现规范

### M01 首页

- 首屏显示三类服务入口。
- 当前报单卡片支持空数据。
- 读取企业和当前报单接口失败时显示可重试状态。

### M02 服务选择

- 服务卡片只允许选择已上架服务。
- 显示资料数量、办理方式和隐私提示。
- 选择后根据 `serviceType` 跳转 M03 或 M05。

### M03 贸易增量清单

- 11 项由后端模板返回，不在前端硬编码业务数量。
- 已上传、待补充、待审核分别展示状态。
- 提交前重新拉取资料项，防止页面停留期间状态过期。

### M04 开票与附件

- 开票信息使用结构化表单。
- 附件按资料项分组上传。
- 上传失败只影响当前文件，不阻塞已成功资料。
- 双列表单中的 `uni-input` 必须使用 `border-box` 且网格子项允许 `min-width: 0`，避免 H5 宽屏下 padding 把输入框撑入相邻列。
- 已保存开票信息进入“重新填写”状态后，底部“保存并继续”必须先执行校验和保存，不能只切换附件页。

### M05 简表单

- 只渲染后端返回的 3 项字段。
- 显示协议勾选状态。
- 商标注册咨询使用 `IP`，资质申报服务使用 `QUALIFICATION`；两类服务复用页面但创建独立报单。
- 成功提交后进入 M06，已提交报单再次打开时只展示脱敏联系电话和只读状态。

### M06 我的报单

- 报单列表支持分页或按需加载。
- 卡片显示状态、完成度和补件说明。
- 无报单、无更多数据和接口异常使用不同状态。
- 打开报单时按 `serviceType` 分流：贸易增量进入 M03，商标和资质进入 M05，不能统一跳转贸易资料页。

## 12. 管理后台规范

### B01 工作台

- 指标卡只展示聚合数字。
- 趋势图数据由接口返回，不在组件内生成业务数字。
- 关注事项可跳转对应报单。

### B02 报单管理

- 筛选条件与 URL query 同步，便于刷新和复制链接。
- 列表分页默认 `pageSize=20`，最大不超过 100。
- 批量操作必须有权限、二次确认和结果反馈。

### B03 产品管理

- 模板发布后不可直接修改，编辑创建新草稿版本。
- 下架保留历史报单引用。
- 新建和上下架动作需要操作日志。

### B04 客户资料

- 列表提供新增客户入口；每行三点图标打开“查看详情、编辑资料、删除客户”操作菜单。
- 查看详情只展示后端返回的脱敏信用代码和脱敏联系电话，不请求或缓存明文。
- 编辑时信用代码、联系电话留空表示保持原值；更新携带 `version`，冲突后提示刷新。
- 删除仅对超级管理员显示，必须二次确认；后端执行软删除并拒绝删除存在未完成报单的企业。
- 新增、编辑、删除都必须显示提交中、成功和失败状态，成功后刷新当前列表。

### B05 逐项审核

- 客户可见说明和内部备注必须分离组件和类型。
- 敏感预览按钮需要额外权限。
- 审核结果保存成功后刷新当前资料项和报单状态。
- 贸易增量报单详情在拥有 `case:credential-handover` 权限时显示“线下凭证交接”。
- 交接板块只允许选择待交接、已线下交接、已核验、已归还或无需交接，不提供密码输入框、文件上传或自由备注。
- 小程序不展示该板块，也不调用对应管理员接口。
- 网银登录密码、U 盾密码、交易密码和短信验证码不得进入 Store、localStorage、请求日志或导出文件。

### B06 导出中心

- 导出任务显示 `PENDING/RUNNING/SUCCEEDED/FAILED/EXPIRED`。
- 轮询间隔建议 2 秒，页面离开后停止轮询。
- 下载前再次检查任务权限和有效期。

### B07 团队与权限

- `/team` 仅允许 `SUPER_ADMIN` 访问，侧边栏对其他角色隐藏入口，路由守卫和后端接口仍需分别校验。
- 页面只管理后台 `ADMIN` 账号，提供成员列表、新建成员、岗位角色调整和当前权限预览。
- 当前登录账号的角色调整按钮禁用，避免管理员误操作导致自己失去管理入口。
- 角色采用 `OPERATIONS`、`REVIEWER`、`SUPER_ADMIN` 三个后台岗位；页面展示的权限来自后端账号响应，不根据用户名猜测。
- 新建后台账号必须填写姓名、用户名、手机号和至少 12 位密码；密码不进入日志、Toast 或页面回显。

## 13. Excel 导入前端规范

导入流程必须包含：

1. 下载模板。
2. 选择或拖放文件。
3. 解析中进度。
4. 预览总行数和错误行数。
5. 确认导入。
6. 查看成功、跳过和失败报告。

拖放区域仅用于后台 Web，不在微信小程序端实现拖放；小程序使用选择文件/图片能力。

错误报告中手机号、税号和账号必须掩码。

## 14. 响应式和适配

### 小程序

- 设计基准：390×844。
- 使用 `rpx` 和安全区变量。
- 底部固定操作条必须预留安全区和滚动空间。
- 长资料列表使用页面滚动，不让固定按钮遮挡最后一项。

### 管理后台

- 设计基准：1440×1100。
- 最小可用宽度建议 1200px。
- 表格在窄屏使用横向滚动容器，不撑破整体布局。
- 关键操作列固定在右侧时必须明确提示横向滚动。

## 15. 无障碍与可用性

- 不能只用颜色表达状态，状态必须同时有文字或图标。
- 可点击元素需要足够触控区域，小程序建议不小于 44×44 px。
- 输入框有明确 label 和错误说明。
- 文件上传失败必须提供可恢复动作。
- 重要删除、导出和提交动作需要确认或撤销提示。

## 16. 前端测试规范

### 单元测试

- 状态字典和格式化函数。
- 表单校验。
- 文件类型、大小和重试状态机。
- 权限按钮判断。

### 组件测试

### 端到端测试

至少覆盖：

1. 创建贸易增量草稿。
2. 填写开票信息并上传文件。
3. 提交后后台审核。
4. 客户收到补件并重新提交。
5. 后台生成 Excel 和 ZIP。

### 18.3 Token 和请求规则

- 后台 Token 只保存在当前标签页的 `sessionStorage`，键名为 `wqst_admin_token`。
- 请求层自动增加 `Authorization: Bearer <token>` 和 `X-Request-Id`。
- 401 会清理 Token，并返回登录页；登录接口自身的 401 只显示“用户名或密码错误”。
- 网络不可达、非 JSON 响应和业务错误统一转换为 `ApiError`。
- 开发环境请求 `/api/v1`，由 Vite 代理到 `http://127.0.0.1:8080`。
- 生产环境默认使用同源 `/api/v1`，部署时需要由网关反向代理到后端。

## 19. OpenAPI 生成 API 规范

前端接口类型以根目录 `openapi/万企商服通_OpenAPI_V1.json` 为唯一契约来源，不在页面中手写重复的请求和响应类型。生成命令为：

```powershell
cd C:\Users\Administrator\Desktop\shopify\wqsf
pnpm api:sync

cd apps/admin-web
pnpm check

cd ../client-uni
pnpm typecheck       # 校验 Vue 页面、Pinia、领域 API、生成 API 和请求适配器
```

生成结果位于：

```text
apps/admin-web/src/api/generated/
apps/client-uni/src/api/generated/
```

这些目录带有 `Do not edit manually` 标记。需要修改接口时修改后端 Controller/record 和 `OpenApiConfig`，重新导出并生成；不要直接改生成文件。

### 19.1 管理后台适配器

`apps/admin-web/src/api/generated-client.ts` 调用 `api/request.ts` 的 `rawApiRequest`，返回完整 `ApiResponse<T>`，因此保留统一错误、401 跳转、Token 和 Request ID 行为。已有页面使用 `apiRequest<T>`，继续得到解包后的 `data`。

页面不得直接调用生成目录。后台领域适配层位于 `apps/admin-web/src/api/{accounts,cases,companies,catalog,exports}.ts`，统一处理请求和业务数据；页面只管理加载、空数据、错误、分页和操作状态。生成目录重新生成后先检查这些适配层的模型导入，再运行 `pnpm check`。

### 19.2 uni-app 适配器和文件上传

`apps/client-uni/src/api/generated-client.ts` 将生成函数转换为 `uni.request`，默认从 `wqst_client_token` 读取令牌。H5 开发使用同源 `/api/v1` 并由 `vite.config.ts` 代理到本地 `8080`，避免浏览器跨域；微信开发构建默认连接 `http://127.0.0.1:8080/api/v1`，也可用 `VITE_API_BASE_URL` 覆盖。正式发布必须把它配置为微信公众平台允许的 HTTPS 合法域名。文件、视频和图片不通过 JSON 发送：使用 `apps/client-uni/src/api/upload.ts` 的 `uploadMaterialFile`，由 `uni.uploadFile` 发送 multipart 请求并返回后端 `data`。

页面只调用 `api/auth.ts`、`api/company.ts`、`api/product.ts`、`api/case.ts` 和 `api/notification.ts` 等领域适配层，不直接导入 `generated/endpoints.ts`。`apps/client-uni/.env.development` 设置 `VITE_CLIENT_AUTH_MODE=dev` 后，“微信登录”按钮通过 `/auth/client/dev-login` 建立本地模拟会话；账号密码入口仍通过 `/auth/client/login` 验证真实本地客户账号。非 development 微信构建执行 `uni.login -> /auth/wechat/login`；账号登录勾选绑定时会重新取得微信 code 并随 `/auth/client/login` 提交。任何正式流程都不会自动回退为开发登录。

本地微信调试命令和导入目录：

```powershell
cd apps/client-uni
pnpm install
pnpm dev:mp-weixin
```

微信开发者工具导入 `apps/client-uni/dist/dev/mp-weixin`。本机模拟器可以访问电脑的 `127.0.0.1`；真机中的 `127.0.0.1` 是手机本身，真机调试应将 `VITE_API_BASE_URL` 改为电脑局域网 IP，并确保手机同网段且 Windows 防火墙放行后端端口。

### 19.3 生成代码的边界

- 生成 API 是接口调用层，不包含页面状态、Toast、表单校验或权限按钮逻辑。
- `operationId` 是生成函数名契约，修改它会造成前端函数名变化，必须在变更记录中说明。
- 后端统一响应包装不会被删除；新增字段优先向后兼容。
- `client-uni` 将所有 DCloud 平台包锁定为同一编译器版本，并将 `@dcloudio/types` 锁定为 `uni-app` 声明的 Peer 版本；`pnpm typecheck` 同时校验页面、Store、领域 API、生成 API 和适配器。
- Orval 当前会生成浏览器专用的 `Headers` 和 `URLSearchParams` 用法。根目录 `pnpm api:generate` 必须在生成后执行 `scripts/patch-uni-generated.mjs`，将请求头判断和查询参数编码改为微信运行时兼容实现；不得只执行裸 `orval`。

### 19.9 客户双登录、绑定和账号切换

小程序启动只恢复本地已有 Token，不自动触发微信授权。无 Token、会话过期或主动退出时统一进入 `/pages/auth/login`，由用户选择：

```text
微信登录
  -> development：/auth/client/dev-login 模拟已绑定账号
  -> 正式微信：uni.login -> /auth/wechat/login -> 仅登录已绑定账号

账号密码登录
  -> /auth/client/login
  -> 正式微信可勾选绑定：重新调用 uni.login，并提交 bindWechat=true + wechatCode
```

- 首次微信使用必须先获得管理员发放的客户账号和密码；后端绑定成功后，下次才能微信一键登录。未绑定时显示后端 `WECHAT_ACCOUNT_UNBOUND` 对应提示，不自动创建无企业关系账号。
- H5 没有微信登录环境，账号密码仍可正常使用；development 的微信按钮仅用于本机模拟，不能用于真实绑定验收。
- `/auth/me` 成功后才将会话状态标记为 ready，页面不能只凭本地 Token 判断已登录。
- 401 会触发全局会话失效事件，清除 Token 后返回登录页；退出登录先调用服务端注销，最终始终清除本地会话。
- 清理范围包括当前用户、企业选择、服务目录、报单草稿，以及 `wqst_create_case_key_*`、`wqst_submit_case_key_*` 幂等键，避免切换账号后读到上一账号的业务缓存。
- “我的”页面的退出/登录其他账号必须二次确认，确认后 `reLaunch` 登录页，不能只跳转但保留旧 Token。

### 19.10 微信 development 占位页排查

- 微信开发者工具只显示 `pages/xxx/xxx.wxml` 时，先检查对应的 `apps/client-uni/dist/dev/mp-weixin/pages/**/**.wxml`，不要直接认定 Vue 页面源码丢失。
- 正常业务 WXML 应包含页面节点和文案；如果文件只有约几十字节、内容是单行 `<text>页面路径</text>`，说明旧 development watcher 没有完整生成新增页面。
- 处理方式是精确停止旧的 `pnpm dev:mp-weixin` / `uni -p mp-weixin` 进程，在 `apps/client-uni` 重新执行 `pnpm dev:mp-weixin`，等待控制台出现 `DONE Build complete. Watching for changes...`。
- 微信开发者工具只导入 `dist/dev/mp-weixin` 做本地联调；重新编译后复核目标 WXML 已包含实际页面内容，并保持 watcher 运行。生产构建的 `dist/build/mp-weixin` 不能替代 development 热更新目录。
- 如果 development WXML 已完整但模拟器仍显示旧页面，关闭重复的旧项目窗口，确认当前项目路径，再执行开发者工具的普通编译；不要同时导入 build 和 dev 两套目录。

### 19.11 我的页面与报单列表分离

- `/pages/mine/index` 只承载当前企业身份、四个报单分类入口、企业资料和账号相关功能，不再直接分页渲染报单卡片；原生导航标题为“我的”。
- 企业身份卡优先显示当前企业名称和成员身份，点击进入 `/pages/company/profile`；不要把登录用户显示名当成企业资料主标题。
- 全部报单、处理中、待补资料、已完成四个统计项必须使用可点击 `button`，统一进入 `/pages/case/list`，查询参数分别是 `all`、`processing`、`supplement`、`completed`。
- `/pages/case/list` 负责筛选标签、分页、空状态、资料完成度和报单详情跳转。处理中必须同时查询 `PENDING_REVIEW,PROCESSING`，避免待审核报单从列表和统计中丢失。
- 首页“查看全部”和当前报单卡片进入全部报单列表；贸易增量、商标、资质提交成功后进入处理中列表；列表卡片继续通过 `caseDetailRoute` 进入对应资料状态页。
- 修改此流程后至少在 390×844 检查“我的”和报单列表，逐一验证四个筛选入口、空列表状态、列表卡片详情跳转以及原生返回行为。

### 19.12 品类匹配与报单二级页

- 自定义底部导航固定为“首页 / 品类匹配 / 我的”；“报单”不再占用 TabBar，从首页“开始报单”“全部服务”或推荐结果进入 `/pages/service/select` 二级页。
- 品类匹配页位于 `/pages/category/match`，沿用白底、墨绿色、金色、圆角卡片和原生导航栏，不照搬参考产品的深色紫色主题。
- 图片通过 `uni.chooseImage` 选择，限制 JPG/JPEG/PNG 和 10MB；`api/category-match.ts` 使用 `uni.uploadFile` 调用 OCR 接口，不能用生成 API 的浏览器 `FormData`。
- OCR 成功后回填公司名称、成立日期、注册资本和经营范围；字段始终允许用户校正。OCR 未配置、识别失败或网络异常时显示可读提示，仍允许手工填写经营范围并调用真实匹配接口。
- 匹配结果按行业分组，显示命中原因和规则分数；无结果时不伪造推荐，提示补充关键词或进入全部服务。
- 报单资料页属于二级流程，不再渲染底部导航。新增页面至少执行 TypeScript、H5/微信构建，并在 390×844 检查表单宽度、长经营范围、推荐列表和固定底栏遮挡。

## 20. TekMark 名片静态还原页

根目录 `tekmark-card.html` 是根据 TekMark 名片设计稿制作的独立静态预览，不接入 `client-uni` 或 `admin-web` 的路由和接口。页面图片统一使用 `https://s3.tkhub.ca/web/assets/email/` 下的 `HeaderImg.png`、`FrameCardImg.png`、`middleImg.png`、`insgramIcon.png`、`FacebookIcon.png` 和 `TiktokIcon.png`；商务背景图和联系人头像暂以同尺寸占位块保留。页脚的 Shop cards、Products、Support 和 Legal 链接，以及页面底部的 GET YOUR OWN CARD 按钮均指向 TekMark 官网对应页面，并使用新窗口打开；个人资料、电子名片下载、社交账号和邮件偏好设置仍需业务方提供目标地址。

Instagram、Facebook 和 TikTok 图标显示尺寸为 26×26 像素；三个社交平台的主页跳转地址仍待提供。

页脚品牌简介区使用“说明文字 + Shop cards 按钮”的两列布局，不通过负外边距叠放；`TekMark Card` 中的 `Mark` 使用品牌蓝色，保证与设计稿一致且文字不会与按钮重叠。

TekMark 邮件模板以 600px 为最大宽度，主体使用嵌套表格和行内样式。头像位于背景图之后的独立表格行，姓名位于下一行，不依赖绝对定位。蓝色按钮采用表格单元格的 `bgcolor` 与行内背景色，页脚简介和 Products、Support、Legal 三栏也使用表格定位；窄屏补充 `@media` 调整字号和排列。发信服务应发送 `tekmark-card.html` 的完整 HTML 内容，并在发送前替换 `{{ owner.first_name }}`、`{{ owner.full_name }}`、`{{ owner.job_title }}` 等字段；头像图片必须插入 `.avatar-placeholder` 内，不能重新使用绝对定位。浏览器预览与真实邮箱渲染仍需分别检查。
